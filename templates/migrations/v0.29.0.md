# Migration: v0.29.0

## Summary
- **Release class:** MINOR (semver compatible). 9 commits since `v0.28.0`:
  2 `feat:`, 3 `fix:`, 3 `docs:`, 1 `chore:` (repo-local, non-consumer);
  no `!:` subjects and no
  `BREAKING CHANGE:` footers. Under conventional-commit semver the honest
  bump is `v0.28.0` → `v0.29.0`. Last tag = `v0.28.0`; intended version =
  `v0.29.0`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for all adopters. No adoption-migration or one-time
  reconciliation this release.
- **Risk:** low. No defaults change, no ownership change, no schema-breaking
  change. The one workflow-affecting shift consumers should know about:
  local-coordinator task closeouts now REQUIRE a fenced decision-record
  block (a one-line routine block is the honest escape when there is no
  decision content), and retirement of completed cards verifies decision
  preservation against COMMITTED reachable state only.

The central thing to understand about this release: **decision knowledge
that survives card retirement stops being attested and starts being
verified.** The retention trilogy (`b788b43` gate v1 → `bb60068` gate v2
corrections → `cccf1b0` the v3 item-enumerated contract) lands a
preservation contract on the `/task-closeout` → `/task-delete` lifecycle:
closeout demands a decision-record block, retirement resolves every
preserved decision ITEM against a committed, branch-reachable carrier, and
the known laundering chains (reported closeout then note replacement;
card-id-only carriers) are refused end-to-end through real ops. Alongside
it, the commit-gate SKIP escape hatch stops implicitly staging everything
in the tree (`f77205e` — a real hazard fix: the operator bypass now
commits the index exactly as left and refuses an empty one), and the
resolve-first skill's disposition contract is corrected from three to four
legal outputs (`74b6e51` — `declined-and-closed` becomes a first-class
terminal disposition: declining is not deferring).

## Watch-outs
1. **Closeout now requires the decision-record block.** The first
   `/task-closeout` after update refuses a closeout that lacks the fenced
   block. When a task genuinely carries no decision content, the honest
   one-liner is `{"version":3,"items":[]}` — routine tasks still retire
   with zero promotion after a clean review.
2. **Retirement verifies COMMITTED state only.** Working-tree content
   never verifies a preservation slot. The recommended carrier pattern is
   the landing commit body itself carrying the card-id anchor (and each
   slot's handle) — commit, then retire.
3. **Post-closeout edits change item identity.** Decision-item ids are
   content-bound; a sanctioned replacement after closeout mints a new id
   and surfaces as a baseline mismatch. The sanctioned amendment is an
   add-only re-closeout — drop/rewrite is refused by design.
4. **The SKIP escape hatch is index-exact.** Operator bypass commits now
   stage explicit paths first (`git add <paths>`); an empty index refuses
   with guidance. This is the fix working, not a regression.
5. **`declined-and-closed` is terminal, not a defer.** Declining an
   optional improvement under resolve-first records inline only — no
   transport card, no debt item. Declining cannot be used to park
   mandatory correctness/safety work.
6. **Legacy cards.** No-record legacy cards are refused at retirement only
   when decision-class fields are non-empty and unpromoted; routine
   legacy closeouts pass untouched.

## Rollback
A minor release is reversible by binary downgrade + re-render: reinstall
the `v0.28.0` binary and `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration ran. **Caveats:**
(a) the corpus reverts with it — the preservation gate disappears
(closeouts stop demanding the block; retirement stops verifying carriers),
the SKIP escape hatch reverts to the hazardous implicit staging, and
resolve-first returns to the three-output contract; (b) decision-record
blocks already written into committed closeout reports are durable docs
and stay inert without the gate; (c) local task cards carrying v3
`decision_record` blocks are gitignored transport — under the older
binary's schema they may fail card validation until retired or edited;
(d) operator-owned config files are not render output and survive both
directions untouched. No other state to undo.
