# Migration: v0.22.0

## Summary
- **Release class:** MINOR (semver compatible). Four additive `feat:`
  capabilities drive the bump — compaction-summary discipline, a
  worker-read-only dynamic worker (Pilot 1), a skill-freshness sentinel, and a
  skill-authoring proposal transport — plus a fail-closed `fix:` to the backlog
  normalizer. No `!:` subjects, no `BREAKING CHANGE:` footers; nothing removes
  or renames a shipped contract, capability, profile, or ownership class. Last
  tag = `v0.21.0`; intended version = `v0.22.0`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Fully automatic for every adopter whose backlog rows are well-formed; the
  four capabilities are additive and opt-in/advisory by default.
- **Risk:** low. Three of the four capabilities are advisory or opt-in
  (sentinel toasts are fail-open; worker-read-only ships unselected;
  skill-proposals adds a new intake surface without promoting anything). The
  compaction-discipline hardens agent behavior (more rigorous compaction
  summaries) without removing capability. The only behavior CHANGE that can
  refuse previously-accepted input is the backlog-normalizer fix, and only for
  rows that were already silently corrupt.

## What changed (consumer-visible only)
| area | change | ships-via | class |
|------|--------|-----------|-------|
| **compaction: compaction-summary discipline** | Substantial compaction summaries now MUST carry five integrity sections (Security/Constraint-Preservation, Attribution-Integrity/Anti-Injection, Findings, Contradictions, Verification) and two global verbatim clauses (security-constraint preservation + user-vs-model attribution). Separately, a content-gated pre-write scan over nine recommended narrative headings is introduced: each heading is required-with-content (emit when it has concrete, non-duplicative content) and forbidden-when-empty (never emit a placeholder/`none`/repetition shell). The hard rules land in `AGENTS.core.md`; the full 9-heading scaffold lands in a new `compaction-discipline` skill. This closes the gap where aggressive compaction silently dropped security constraints or mis-attributed model-generated text as user turns. | `templates/core/` (AGENTS.core.md hard rules + compaction-discipline skill, rendered to `.opencode/`) | non-breaking (additive discipline; agents keep all prior capability) |
| **worker: worker-read-only dynamic worker (Pilot 1)** | A prompt-scoped read-only dynamic worker, opt-in via the new `core/worker-read-only` capability (modeled on `core/media-perception`). Complements durable specialists via "process is value; prompt is scope" routing: when the dispatch prompt itself completely bounds a focused read-only inspection, route to the worker instead of a durable specialist. Deny-first permissions — no edit/task/web/skill, read-only shell, deny-all delegation, no `exec-sandbox`. Ships UNSELECTED; `worker-execute` is deliberately deferred pending edit-fence evidence. | `templates/core/` (agent + capability, rendered to `.opencode/agents/` and the capability list) | non-breaking (opt-in; inert until the capability is selected) |
| **sentinel: skill-freshness sentinel in session-state plugin** | Detects rendered-skill staleness across sessions and emits ONE truthful restart-required notice. At `server()` init the session-state plugin fingerprints `.opencode/skills/*/SKILL.md` files (SHA-256 + sorted-pair aggregate); on `session.created` it recomputes and compares, and on diff emits a deduped warning toast. Read errors surface as a distinct error notice. Difference-only semantics mirror `corpus_freshness.go` (no chronology claim). Advisory and fail-open by design. | `templates/core/` (session-state plugin, rendered to `.opencode/`) | non-breaking (advisory toast; fail-open on read error) |
| **skill-proposals: skill-authoring proposal transport** | A new local candidate transport at `.local/coordinator/skill-proposals/` where models can propose skills as structured draft cards. Human accepts/rejects (documentation-level enforcement, same pattern as task cards; mechanical gates downstream: overlay authoring → S2 hold → pilot → evidence → core promotion). Provenance is stamped as nested `metadata.proposal-origin` (top-level `created_by` refused); `/init` direct-write is rejected. New `/skill-propose` command (create/list/open/accept/reject/delete) plus five plan-state operations. Acceptance creates NOTHING — it only records approval to proceed with separately authorized overlay authoring. | `templates/core/` (`/skill-propose` command + plan-state operations + AGENTS.md workflow rules, rendered to `.opencode/`) | non-breaking (new intake surface; gitignored transport; creates no skill and promotes nothing) |
| **backlog normalizer: refuse rows that do not have exactly seven cells** | `parseTaskRow` previously improvised when a row split into other than seven cells: it padded short rows with empty cells and, for rows with MORE than seven cells, guessed the overflow came from the Notes column and joined cells with `" \| "`. When the stray pipe sat in an EARLIER column (e.g. an unescaped `\|\|` in a Task cell), that guess silently mis-assigned columns and `writeOutputs` then persisted the corruption. This release replaces the guess with a fail-closed `BacklogError` that names the row, the expected count (7), the actual count, and the remedy (escape stray pipes as `\|`). A cell count LESS than seven is refused too — the contract is "exactly seven," not "at least seven." | `templates/core/.opencode/scripts/normalize-backlog.js` (rendered to `.opencode/scripts/normalize-backlog.js`, `platform_managed`) | non-breaking for well-formed backlogs; deliberate fail-closed behavior change for malformed rows (the previous silent repair was the bug) |
| **backlog normalizer: remove a fabricated task ID from the generated archive index** | `renderArchiveIndexFile` emitted `rg "P0-DOCS-006" ...` as retrieval guidance into every adopter's generated `docs/planning/archive/index.md`. `P0-DOCS-006` exists nowhere as a real task — anyone who followed the guidance got zero results. It also violated the `templates/core/` domain-free rule. Replaced with a placeholder that points at the ID column without naming an ID: `rg "<TASK_ID>" ...`. | same script, rendered output | non-breaking (guidance text only) |

## How to migrate (automated)
For the vast majority of adopters: nothing beyond the standard re-render. Three
of the four capabilities are inert until you opt in (worker) or simply advisory
(sentinel); the fourth (skill-proposals) adds a command you may use optionally;
the compaction-discipline improves agent behavior with no action required.

```bash
vh-agent-harness self-update            # pull the new binary (v0.22.0)
vh-agent-harness version                # expect: 0.22.0 (<label>)
vh-agent-harness update --dry-run       # ownership-safe preview of the re-render
vh-agent-harness update                 # applies platform_managed + active overlay_extension
vh-agent-harness doctor                 # lint the result
```

To opt into the worker-read-only dynamic worker, list `core/worker-read-only`
under `capabilities:` in `.vh-agent-harness/vh-harness-profile.yml` (it is a
core opt-in capability, NOT an overlay pack — overlay packs resolve by bare
name from `templates/overlays/<name>/` and an unknown pack name fails closed),
then re-render. To use the skill-proposals intake, run `/skill-propose create`
(cards land under `.local/coordinator/skill-proposals/`, which is gitignored
transport).

If the normalizer now refuses a row, the error message names the offending row
ID and the cell count, e.g.:

```
Expected 7 cells but found 9 for P1-FOO-002 in Now: escape stray pipes as \|
```

Fix the row by escaping every literal pipe inside a cell as `\|` (so an
unescaped `||` becomes `\|\|`). For example, a Task cell
`if (added || upgraded)` must be written `if (added \|\| upgraded)`. Then
re-run the normalizer.

## Exposure (precise)
- **compaction-discipline:** surfaces in every substantial compaction a session
  performs (the five integrity sections + the two verbatim clauses become
  mandatory). No gate; agent-output discipline only.
- **worker-read-only:** surfaces only in sessions whose profile selects the
  `core/worker-read-only` capability AND a dispatch routes to it. Inert
  otherwise.
- **sentinel:** surfaces as a toast on `session.created` when rendered skill
  files changed since the running session's in-process cache was built (i.e.
  after a `vh-agent-harness update` that touched skills, while a session is
  still running). Advisory; fail-open on read error.
- **skill-proposals:** surfaces as the `/skill-propose` command and the
  `.local/coordinator/skill-proposals/` directory. No automatic promotion.
- **backlog normalizer:** surfaces when a **promoter or operator runs the
  normalizer** — i.e. the `/backlog-cleanup` step in
  `docs/coordination/PROMOTER_RUNBOOK.md` (or any direct
  `vh-agent-harness exec node .opencode/scripts/normalize-backlog.js`
  invocation). It is **NOT** an automatic commit block: `commit-gate.sh` does
  not execute the normalizer (it only references the command inside a recovery
  message). A well-formed backlog is unaffected.

## What `update` handles for you
- Re-renders `AGENTS.core.md` with the compaction-discipline hard rules and the
  new `compaction-discipline` skill under `.opencode/skills/`.
- Renders the `worker-read-only` agent and capability (inert until selected).
- Renders the session-state plugin with the skill-freshness sentinel.
- Renders the `/skill-propose` command and the five plan-state operations, plus
  the AGENTS.md workflow rules for the proposal intake.
- Re-renders `.opencode/scripts/normalize-backlog.js` from the fixed source
  (`platform_managed`, overwritten on every `update`). The next time the
  normalizer runs, it also rewrites `docs/planning/archive/index.md` so the
  fabricated `P0-DOCS-006` example is replaced by the `<TASK_ID>` placeholder.
  (That file is generated by the normalizer, not by `update`; it refreshes on
  the next normalize run.)

## Watch-outs
1. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers
   rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the
   binary first), NEVER a bare `vh-agent-harness update` — the stale-embed guard
   refuses a live `update` when the embedded corpus differs from
   `templates/core/`.
2. **worker-read-only is Pilot 1 and opt-in.** It ships UNSELECTED. Selecting it
   adds a dynamic read-only worker to your dispatch surface; do not select it
   unless you want prompt-scoped read-only inspection routing. `worker-execute`
   (an editable dynamic worker) is deliberately deferred.
3. **sentinel is advisory and fail-open.** A read error in the skill-fingerprint
   path surfaces as an error notice, never blocks the session.
4. **skill-proposals acceptance creates nothing.** `/skill-propose accept <id>`
   records human approval to proceed with separately authorized overlay
   authoring; it installs no skill and promotes nothing. A model cannot accept
   its own proposal.
5. **Escape symmetry is preserved (backlog normalizer).** `unescapeTableCell`
   (parse) and `sanitizeCell` (render) are unchanged; a properly escaped
   `\|\|` still round-trips byte-identically. Only the cell-COUNT contract
   changed.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.21.0`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible state.
The four capabilities disappear on rollback (they are additive corpus). Rolling
back the backlog-normalizer fix restores the previous improvising behavior, so
any row that this release would refuse will once again be silently repaired
(and potentially mis-assigned) — re-inspect previously-refused rows before
relying on the output.
