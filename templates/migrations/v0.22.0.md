# Migration: v0.22.0

## Summary
- **Release class:** MINOR (semver compatible). This note covers the
  `normalize-backlog.js` behavior change in this arc. Last tag = `v0.21.0`;
  intended version = `v0.22.0` (the arc since `v0.21.0` already carries
  additive `feat:` commits, so the release that ships this fix is a MINOR bump).
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Fully automatic for every adopter whose backlog rows are well-formed.
- **Risk:** low. The fix turns a previously-silent data-corruption path into an
  explicit refusal. Adopters with well-formed rows (every row already has
  exactly seven pipe-separated cells) see no change. The only adopters affected
  are those with a backlog row containing an UNescaped `|` inside a cell: where
  the normalizer previously guessed at the column layout (and could silently
  mis-assign cells and persist the corruption on the next write), it now refuses
  with a clear error naming the row to fix.

## What changed (consumer-visible only)
| area | change | ships-via | class |
|------|--------|-----------|-------|
| **backlog normalizer: refuse rows that do not have exactly seven cells** | `parseTaskRow` previously improvised when a row split into other than seven cells: it padded short rows with empty cells and, for rows with MORE than seven cells, guessed the overflow came from the Notes column and joined cells with `" \| "`. When the stray pipe sat in an EARLIER column (e.g. an unescaped `\|\|` in a Task cell), that guess silently mis-assigned columns and `writeOutputs` then persisted the corruption. This release replaces the guess with a fail-closed `BacklogError` that names the row, the expected count (7), the actual count, and the remedy (escape stray pipes as `\|`). A cell count LESS than seven is refused too — the contract is "exactly seven," not "at least seven." | `templates/core/.opencode/scripts/normalize-backlog.js` (rendered to `.opencode/scripts/normalize-backlog.js`, `platform_managed`) | non-breaking for well-formed backlogs; deliberate fail-closed behavior change for malformed rows (the previous silent repair was the bug) |
| **backlog normalizer: remove a fabricated task ID from the generated archive index** | `renderArchiveIndexFile` emitted `rg "P0-DOCS-006" ...` as retrieval guidance into every adopter's generated `docs/planning/archive/index.md`. `P0-DOCS-006` exists nowhere as a real task — anyone who followed the guidance got zero results. It also violated the `templates/core/` domain-free rule. Replaced with a placeholder that points at the ID column without naming an ID: `rg "<TASK_ID>" ...`. | same script, rendered output | non-breaking (guidance text only) |

## How to migrate (automated)
For the vast majority of adopters: nothing. Re-render the corpus and the
normalizer continues to accept the same rows.

```bash
vh-agent-harness self-update            # pull the new binary
vh-agent-harness version                # expect: 0.22.0 (<label>)
vh-agent-harness update --dry-run       # preview the re-rendered normalize-backlog.js first
vh-agent-harness update                 # re-render .opencode/scripts/normalize-backlog.js
vh-agent-harness doctor                 # lint the result
```

If the normalizer now refuses a row, the error message names the offending row
ID and the cell count, e.g.:

```
Expected 7 cells but found 9 for P1-FOO-002 in Now: escape stray pipes as \|
```

Fix the row by escaping every literal pipe inside a cell as `\|` (so an
unescaped `||` becomes `\|\|`). For example, a Task cell
`if (added || upgraded)` must be written `if (added \|\| upgraded)`. Then
re-run the normalizer.

## Exposure (precise)
The failure surfaces when a **promoter or operator runs the normalizer** —
i.e. the `/backlog-cleanup` step in `docs/coordination/PROMOTER_RUNBOOK.md`
(or any direct `vh-agent-harness exec node .opencode/scripts/normalize-backlog.js`
invocation). It is **NOT** an automatic commit block: `commit-gate.sh` does not
execute the normalizer (it only references the command inside a recovery
message). A well-formed backlog is unaffected.

## What `update` handles for you
- Re-renders `.opencode/scripts/normalize-backlog.js` from the fixed source
  (`platform_managed`, overwritten on every `update`).
- The next time the normalizer runs, it also rewrites
  `docs/planning/archive/index.md` so the fabricated `P0-DOCS-006` example is
  replaced by the `<TASK_ID>` placeholder. (That file is generated by the
  normalizer, not by `update`; it refreshes on the next normalize run.)

## Watch-outs
1. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers
   rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the
   binary first), NEVER a bare `vh-agent-harness update` — the stale-embed guard
   refuses a live `update` when the embedded corpus differs from
   `templates/core/`.
2. **Escape symmetry is preserved.** `unescapeTableCell` (parse) and
   `sanitizeCell` (render) are unchanged; a properly escaped `\|\|` still
   round-trips byte-identically. Only the cell-COUNT contract changed.

## Verification commands
```bash
vh-agent-harness exec node .opencode/scripts/normalize-backlog.js --check   # well-formed backlog: "Pending file updates: none", exit 0
vh-agent-harness doctor                                                     # expect HEALTHY
```
For the behavior change specifically:
```bash
vh-agent-harness exec node --test tests/scripts/normalize-backlog.test.js   # 3 tests: refusal, escape round-trip, no task-ID in archive index
```

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.21.0`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible state.
Rolling back restores the previous improvising behavior, so any row that this
release would refuse will once again be silently repaired (and potentially
mis-assigned) — re-inspect previously-refused rows before relying on the output.

## Non-consumer changes
The supporting work for this change includes the three black-box tests at
`tests/scripts/normalize-backlog.test.js` (refusal on a bad cell count, escape
round-trip, no task-ID shape in the rendered archive index) and this migration
note. None of these ship to consumers (the test file lives outside
`templates/core/` and does not render).
