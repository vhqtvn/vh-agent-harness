# Migration: v0.19.0

## Summary
- **Release class:** MINOR (semver compatible). The `v0.18.0..HEAD` arc (94
  commits) is an **additive feature** release dominated by the
  recurrence-signature + dedup-enforcement family (P1-MEMORY-001) and a Go
  task-card validator port, plus a kernel-floored exec-sandbox Level-B, a
  fail-closed repo-mail egress gate, commit-scope integrity (S1+S2), and a
  complexity advisory foundation. It carries **22 `feat`** commits, **6 `fix`**
  commits, **zero `!:` subjects**, and **no `BREAKING CHANGE:` footers** → MINOR
  bump; not patch (real consumer-facing behavioral additions across the embedded
  Go binary and the re-rendered corpus), not major (every edit is additive — no
  shipped contract, capability, or profile change is removed or renamed in a
  way that breaks a default consumer). No profile, ownership-class,
  capability, or runtime change is required; the default consumer's
  `opencode.jsonc` is byte-identical unless an active overlay alters it. Last
  tag = `v0.18.0`; intended version = `v0.19.0`.
- **Upgrade path:** binary self-update, then re-render the corpus. Fully
  automatic for the default consumer. The recurrence-ack release-gate
  enforcement, the recurrence doctor diagnostics, the Go task-card validator
  (retiring the Python `jsonschema` script), the syntax-quarantine of corrupt
  registry cards, the exec-sandbox Level-B mode/net-floor enforcement, the
  repo-mail egress gate, the commit-scope integrity rules, the complexity
  advisory check #20, the schema_v2 review-tiers panel, the stakes-based
  commit-reviewer seat routing, and the malformed-predicate detection all ship
  in the embedded Go binary and/or the embedded corpus (re-rendered by
  `update`). `templates/core/` remains domain-free (token-only; no adopter/overlay
  identifier in any source or rendered file). Source-builders rebuilding from
  this tag are unaffected (no Go toolchain bump).
- **Risk:** low. Every change is additive. The recurrence-ack enforcement is
  the one new fail-closed gate surface (doctor #12 + the release-tag DEFER
  gate): it refuses a release tag only when a recurrence-bearing defer carries
  an acknowledged-count BELOW the live derived count, or when an uncollapsed
  duplicate (≥2 cards sharing an effective recurrence id) exists — both dormant
  when no release is imminent and when recurrence records are absent. The Go
  task-card validator is behavior-equivalent to the retired Python `jsonschema`
  script (same schema, same verdicts) with no Python runtime dependency. The
  exec-sandbox Level-B mode-floor/net-floor is enforced on the binary side and
  activates only for agents granted `exec-sandbox` (Level-B read-only agents);
  host-shell agents are unaffected. The complexity advisory check #20 is an
  advisory INFORM that is **disabled by default this release** (ships as
  structure; the advisory is gated off until the agent-context axis raises
  precision), so it cannot change a doctor exit code today. The repo-mail
  egress gate is fail-closed (domain-free: denies unless explicitly allowed),
  scoped to the repo-mail pack only.

## Watch-outs
1. **The recurrence-ack gate is fail-closed but dormant by default.** Doctor #12 and the release-tag DEFER gate refuse a release ONLY when a recurrence-bearing defer carries an acknowledged-count below the live derived count, or when an uncollapsed duplicate (≥2 cards sharing an effective recurrence id) exists. Repos with no recurrence records (the common case) are unaffected. The remedy when it fires is operator re-adjudication (bump the manifest's `last_acknowledged_count`), NOT a code change — do not edit code to work around it.
2. **The complexity advisory is disabled by default this release.** Check #20 ships as structure but is gated off (the advisory is off until the agent-context axis raises precision). It cannot change a doctor exit code today; enabling it is a future release's decision.
3. **exec-sandbox Level-B is host-local.** The mode-floor/net-floor is kernel-enforced only when the sandbox is active (`--sandbox=off|best-effort|strict`, default best-effort). It activates only for agents granted `exec-sandbox`; host-shell (`exec`) agents are unchanged.
4. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the binary first), NEVER a bare `vh-agent-harness update` — a bare update would silently overwrite in-progress `.opencode/` work with a stale embedded corpus (the stale-embed guard refuses a live `update` when the embedded corpus differs from `templates/core/`). GoReleaser rebuilds for the published artifact regardless.
5. **Three non-blocking DEFER disclosures** (operator visibility; no consumer action required; all `release_relevance=yes` + `disclose` + `valid`, surfaced as non-blocking WARNINGs):
   - `defer-011-cas-conflict-recovery-doc-drift` — recovery docs (`committer.md`, `docs/coordination/README.md`) still teach the obsolete `cas_conflict` status term after P0-B Slice B converted the `merge_failed`/`write_tree_failed` sites to `could_not_land`; the shipped binary is correct (the gate emits `could_not_land`), only the recovery-doc prose is stale.
   - `defer-014-closeout-ledger-flock-absent-coverage` — the closeout-ledger flock-absent non-Linux fallback is structurally sound but not behaviorally exercised under CI (Go tests run on Linux where `flock` is present); defense-in-depth, pre-existing, not worsened this arc.
   - `normalizer-archive-companion-tension` — pre-existing backlog-split design tension (the O1 gate forces `backlog.md` to commit alone, including vs `archive/*` companions); the two-commit landing is a working workaround, not worsened this arc.
   The remaining records are `release_relevance=no` disclosures carried for audit completeness (including one retained `metadata_state: invalid` legacy card `defer-p1-lineage-002-001` whose `||`-chain trigger grammar is now correctly flagged malformed by the new predicate detection).

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness` binary (e.g. `v0.18.0`), then `vh-agent-harness update` to re-render the corpus from that binary's embedded corpus. No data migration; no irreversible state. The recurrence-ack enforcement, the Go task-card validator, the syntax-quarantine, the exec-sandbox floor, the repo-mail gate, the commit-scope integrity rules, and the complexity advisory are all additive — a prior binary simply does not exercise them, and re-rendering from a prior binary's corpus restores the prior scripts. Source-checkout consumers rolling back MUST use `make update` against the prior tag (the `Makefile` target rebuilds first), not a bare `update`.
