# Migration: v0.17.0

## Summary
- **Release class:** MINOR (semver compatible). The `v0.16.0..HEAD` arc (6
  commits) is a focused **consumer-portability repair + render-time guard**
  release targeting a single named defect class: the *consumer-render
  source-checkout-only-path* assumption. The arc carries **1 `feat`** commit
  (`c13fdaa`), **1 `fix`** commit (`b69fb1f`), **zero `!:` subjects**, and **no
  `BREAKING CHANGE:` footers** → MINOR bump; not patch (a real consumer-facing
  behavioral addition), not major (no breaking change). Every change is either
  additive (a new render-time regression guard) or a repair (consumer-relative
  path/heuristic fixes that restore correct behavior in non-Go consumer renders
  with no `templates/core/`). No profile, ownership-class, capability, or
  runtime change is required; the default consumer's `opencode.jsonc` is
  byte-identical. Last tag = `v0.16.0`; intended version = `v0.17.0`.
- **Upgrade path:** binary self-update, then re-render the corpus. Fully
  automatic for the default consumer. The new render-time guard and the three
  repaired verifiers/doc surfaces ship in the embedded corpus (re-rendered by
  `update`). `templates/core/` remains domain-free (token-only; no
  adopter/overlay identifier in any source or rendered file). Source-builders
  rebuilding from this tag are unaffected (no Go toolchain bump).
- **Risk:** low. The new render-time guard (`verify-no-source-tree-only-paths.js`)
  is a **no-op in source-checkout mode** and only exits non-zero in
  consumer-render mode when a shipped file references a path/heuristic that
  resolves only in the harness source checkout — it can only fail a
  verification, never force one. The three repaired surfaces (TA-1/TA-2/TA-3)
  restore correct behavior in consumer renders that previously exited
  ENOENT / exit-1 / wrong-root. Base consumers (no overlays) are
  false-positive-free.

## What `update` handles for you
- Re-renders the new `verify-no-source-tree-only-paths.js` render-time guard into `.opencode/scripts/` (ships via the embedded corpus).
- Re-renders the three repaired consumer-portability files — `verify-f3-authoring-surfaces.js` (TA-1), `verify-no-unrendered-paths.js` (TA-2), and the `build.md`/`approve-plan.md`/`task-ready.md` F3 citations (TA-3) — with the source-checkout-only-path assumptions removed.
- No profile, ownership-class, capability, or runtime change; the default consumer's `opencode.jsonc` is byte-identical unless an active overlay alters it.

## Watch-outs
1. **Overlay false-positive surface (known limitation, documented in-script).** The render-time guard's CORE-only allowlist cannot name overlay-contributed files without coupling core to non-core content. A consumer selecting an overlay whose files carry descriptive `templates/core` references (e.g. the shipped release overlay's `releaser.md`) is a false-positive surface for Part A. Base consumers (no overlays) are false-positive-free. Re-evaluate when an affected overlay is selected.
2. **Source-checkout repos (this dev/dogfood repo).** The guard is a no-op in source-checkout mode. Source-checkout consumers rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the binary first), NEVER a bare `vh-agent-harness update` — a bare update would silently overwrite in-progress `.opencode/` work with a stale embedded corpus (the stale-embed guard refuses a live `update` when the embedded corpus differs from `templates/core/`). GoReleaser rebuilds for the published artifact regardless.
3. **Two non-blocking DEFER disclosures** (operator visibility; no consumer action required). `defer-011` (`release_relevance=yes` + `disclose` + `valid`): a `/task-ready` command-template prose gap that is fail-closed-safe — the F3 gate at `state-lib.js::readyCoordinationTask` refuses `draft→ready` regardless of command-template prose, so shipping without the explicit authoring step cannot weaken enforcement. The underlying gap was already resolved in a prior release, so this disclosure is over-satisfied. `defer-p1-lineage-002-001` (`release_relevance=no` + `disclose` + `invalid`): a retained conditional follow-up for P1-LINEAGE-002 F6/F7 with invalid legacy `||`-chain trigger grammar; the trigger was not met for this arc; re-evaluate only when a prune phase is pursued.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness` binary (e.g. `v0.16.0`), then `vh-agent-harness update` to re-render the corpus from that binary's embedded corpus. No data migration; no irreversible state. Source-checkout consumers rolling back MUST use `make update` against the prior tag (the `Makefile` target rebuilds first), not a bare `update`.
