# Migration: v0.27.0

## Summary
- **Release class:** MINOR (semver compatible). 30 commits since `v0.26.2`:
  3 `feat:`, 5 `fix:`, 22 docs/test/chore; no `BREAKING CHANGE:` footers and
  no `<type>!:` subjects. Under conventional-commit semver the honest bump is
  `v0.26.2` → `v0.27.0`. Last tag = `v0.26.2`; intended version = `v0.27.0`.
  (One of the three feats — the dogfood researcher-steps overlay raise — is
  repo-local; the MINOR signal stands on the two shipped feats regardless.)
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for all adopters — no adoption-migration or one-time
  reconciliation this release.
- **Risk:** low. The headline changes are additive or hardening: a frozen
  greenfield install recipe + bootstrap inventory ledger, capability-
  conditional git-routing guidance (rendered corpus prose + ADVISORY doctor
  diagnostics), a permissive run-shape schema acceptance (`docker_compose`
  alongside `docker-compose`), auto-gate classifier judgment-scope bounds
  (embedded sys-prompt + opt-in pilot overlay), an f2 admission-gate
  extension to media-attachment locators, a JSONC-tolerant shell-guard
  grant-naming reader, and corpus domain-free cleanups. No shipped contract,
  capability, profile, or API surface has a breaking change.

No adoption-migration reconciliation this release. Attention points: the
auto-gate sys-prompt clauses serve only after the binary rebuild baked into
`self-update` AND an OpenCode host restart (the plugin module cache holds
pre-update code until restart); the `auto-classifier-pilot` and `release`
packs do nothing until listed under `overlays:`.

## Watch-outs
1. **Auto-gate bounds are heuristics, not a proven fix.** The two sys-prompt
   clauses bound deny-shaped heuristics (prose-writes judged as writes;
   dispatched scope intent) but the live classifier's verdict on them is
   unverified until a verdict-level live receipt exists — no release or
   closeout claim may state the v0.27.0 misfire class is "resolved" without
   it (tracked as the defer-021 verdict-receipt obligation). The clauses
   also require an OpenCode host restart to serve.
2. **`auto-classifier-pilot` is opt-in.** Denial-feedback sanitization and
   per-leaf reasons render only under `overlays: [auto-classifier-pilot]`;
   adopters not selecting the pack see no plugin change.
3. **Dual-spelling is permissive, not a rename.** Both `docker_compose` and
   `docker-compose` validate; the vocabulary rule is prose-only. No config
   change is required (files using either spelling keep working).
4. **Greenfield recipe affects NEW installs only.** Existing installs get no
   forced migration; the frozen recipe and inventory ledger govern future
   greenfield installs and future shipped-surface decisions.
5. **Capability-coherence diagnostics are advisory.** Doctor surfaces
   missing agent blocks / caller task edges when a capability is selected;
   the check INFORMS and never gates.
6. **Source-checkout repos (this dev/dogfood repo).** Rebuild locally with
   `make update` (never a bare `vh-agent-harness update` — the stale-embed
   guard refuses when the embedded corpus differs from `templates/core/`);
   `make doctor` for health. Consumers whose binary embeds the same corpus
   they run with are unaffected.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.26.2`), then `vh-agent-harness update` (source-checkout
repos: `make update` against the prior tag). No data migration; no
irreversible state. Rolling back removes the greenfield frozen recipe +
inventory ledger, the capability-conditional routing guidance and advisory
diagnostics, the auto-gate prompt bounds and pilot-overlay feedback fixes,
the f2 media-attachment admission extension, the JSONC-tolerant grant-naming
reader, and the corpus cleanups — and re-tightens the run-shape backend enum
to `docker_compose` only (a config file using the `docker-compose` spelling
would re-fail schema validation under the older binary; keep the canonical
token if you plan to roll back).
