# Migration: v0.28.0

## Summary
- **Release class:** MINOR (semver compatible). 12 commits since `v0.27.0`:
  6 `feat:`, 2 `fix:`, 1 `refactor:`, 3 test; no `!:` subjects and no
  `BREAKING CHANGE:` footers. Under conventional-commit semver the honest
  bump is `v0.27.0` → `v0.28.0`. Last tag = `v0.27.0`; intended version =
  `v0.28.0`. (One feat is dogfood-local — the Phase-2 audit pack selection
  in this repo's own profile; the MINOR signal stands on the five shipped
  feats regardless.)
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for all adopters. No adoption-migration or one-time
  reconciliation this release.
- **Risk:** low, with ONE deliberate defaults change consumers should know
  about: the rendered per-agent `steps` budgets rise from the inherited
  20–60 tier to a uniform dead-man backstop of 10000 on the 12 capped
  agents. Non-breaking for renders (the key simply changes value), but
  anyone relying on the old tight budgets for cost control should re-tighten
  per-agent via an overlay append (see Watch-outs).

The central thing to understand about this release: **the unattended-session
fence story moves forward on two fronts — a uniform dead-man backstop that
ships to everyone, and a new opt-in pilot pack that adds LLM-judged loop
detection.** The backstop (`69e2431`) replaces the per-agent steps tier
inherited from the trueai lineage (never measurement-derived) with
`steps: 10000` on all 12 capped agents, so long/overnight sessions no longer
die at 30–60 model iterations. The new `session-progress-pilot` pack
(`a38fa4d` + `269d9c9` + `0e08cb9` + `840d6b8`) detects looping tool calls
via a single `tool.execute.before` hook, with deny-only teeth, audit-first
adoption, and fail-open on every error path. The two are designed together
but ship independently: the backstop goes to every consumer on `update`; the
pack is double opt-in (select the pack AND name agents in config) and
renders nothing until both. Alongside them, three hardening rows land in the
existing opt-in `auto-classifier-pilot` pack (raw fault-egress fix, path
anchoring, dead reserve-hook removal). Adopt the pack in AUDIT first; never
read it as making sessions "safely bounded" — the steps backstop remains the
spend bound.

### Enabling session-progress-pilot (audit first)

1. Add `session-progress-pilot` under `overlays:` in
   `.vh-agent-harness/vh-harness-profile.yml`.
2. `vh-agent-harness update --dry-run` → confirm the pack renders →
   `vh-agent-harness update`.
3. Restart opencode — plugins load at process start (module bytes are
   cached per process; a running host will not pick the new plugin up).
4. Wire a judge: create `~/.config/vh-agent-harness/session-progress-llm.json`
   with `{endpoint, model, apiKey}` pointing at an OpenAI-compatible
   chat-completions endpoint. **Verify the model accepts `temperature: 0`**
   (the judge request pins it; a real incident in this arc: a
   temperature:0-rejecting kimi tier produced 8× judge HTTP 4xx until the
   judge model was switched).
5. Opt agents into audit: `.opencode/repo-configs/session-progress.local.json`
   → `{"enabled":true,"agents":{"*":"audit"}}`. The config is mtime-hot —
   edits take effect on the next tool call, no restart.
6. Watch `tmp/agent-runs/session-progress-pilot/verdicts.jsonl`. Graduate an
   agent to `"enforce"` only after its audit verdicts look correct.

(new pack plugins; re-rendered auto-classifier plugins) load.

## What `update` handles for you
- Re-renders `opencode.jsonc` with the uniform `steps: 10000` backstop on
  the 12 capped agents (uncapped executors keep no `steps` key).
- Distributes the embedded `session-progress-pilot` pack; renders it into
  `.opencode/` ONLY when listed under `overlays:` — and even then every
  agent starts `off` until config opts in.
- For consumers selecting `auto-classifier-pilot`: re-renders the plugins
  with the fault-egress sentinel, marker-anchored path resolution, and the
  reserve-hook removal.
- Renders the `README.agent.md` pack documentation (shipped-overlay list,
  config reference pointer).
- No profile, ownership-class, capability, agent-identity, command-verb, or
  runtime change beyond the above. Everything tagged `local_adopted` or
  inactive `overlay_extension` is preserved as before.

## Watch-outs
1. **The steps backstop is a defaults change.** Agent step budgets rise
   from the 20–60 tier to 10000 on the 12 capped agents. If you relied on
   the old tight budgets for cost control, re-tighten per-agent via an
   overlay append (`opencode-append.jsonc` in a project-local pack) — the
   backstop is a dead-man fence, not a tuned allocation.
2. **The pack is double opt-in.** Selecting `session-progress-pilot` under
   `overlays:` renders the plugin, but every agent remains `off` until
   `session-progress.local.json` names it (or `"*"`) as `audit`/`enforce`.
   With no config the hook is config-load + allow and nothing else: no
   records, no diagnostics, no judge calls, zero LLM spend. Default
   consumers (who do not select the pack) get nothing of it at all.
3. **Judge latency is real.** Measured real-gateway latencies (commit-time measurement per
   `840d6b8`; not re-measured for this note): no sampled model answered
   the judge prompt in under 6 s (a configured kimi judge ~11 s;
   fast-branded tiers 14–18 s). A judged call may hold the tool call
   for up to the 20000 ms deadline (default AND clamp ceiling,
   down-configurable via `judge.timeout_ms`, never above 20000), at most
   once per 60 s per session and only after ≥8 new observations. At
   deadline → allow (fail-open), never abort.
4. **`temperature: 0` model compatibility.** The judge request pins
   `temperature: 0`; some tiers reject it (this arc's real incident: 8×
   judge HTTP 4xx until the judge model was switched; commit-time
   measurement per `840d6b8`, not re-measured for this note). Verify your judge
   model accepts it before concluding the wiring is broken.
5. **No "safely bounded" claims.** The detector is a PILOT with a
   deliberately narrow deny surface; the `steps: 10000` backstop remains
   the only hard spend bound on unattended sessions. Adopt audit-first;
   graduate to `enforce` per-agent only on audit evidence.
6. **Restart required after `update`.** Plugin bytes are cached per
   opencode process; a running host serves pre-update plugins until
   restarted. (Repo-config changes later are mtime-hot — no restart — but
   plugin load itself is process-start.)

## Rollback
A minor release is reversible by binary downgrade + re-render: reinstall
the `v0.27.0` binary and `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration ran. **Caveats:**
(a) the steps re-render inverts — the 20–60 per-agent tier returns on the
next render with the older binary (any overlay re-tightening you added
survives as your own overlay and layers on top); (b) the older binary does
not embed `session-progress-pilot`, so a consumer who selected it must drop
it from `overlays:` or keep a project-local pack at
`.vh-agent-harness/overlays/session-progress-pilot/` (project-first seam)
before re-rendering, and the pack files the newer binary rendered
(`.opencode/plugins/session-progress.js`,
`.opencode/scripts/session-progress-{config,judge,policy}.js`) are not
known to the older renderer — remove them manually if unwanted:
```bash
git checkout HEAD -- .opencode/         # only if an unrelated render diff is unwanted
rm .opencode/plugins/session-progress.js \
   .opencode/scripts/session-progress-{config,judge,policy}.js  # the four untracked pack renders named above; git checkout does not remove them — delete if unwanted
```
(c) the three `auto-classifier-pilot` hardening rows revert with the pack's
older plugin bytes (pack consumers only); (d) operator-owned config files
(`session-progress.local.json`, the user-level judge JSON) are not render
output and survive both directions untouched. No other state to undo.
