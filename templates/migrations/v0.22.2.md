# Migration: v0.22.2

## Summary
- **Release class:** PATCH (semver compatible). Three `fix:` since `v0.22.1`,
  zero `feat:`/`!:`/`BREAKING CHANGE:`. No shipped contract, capability,
  profile, ownership class, or API surface changes — this is a narrow
  output-honesty bug-fix arc. Last tag = `v0.22.1`; intended version = `v0.22.2`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Fully automatic; no manual migration step is required for any adopter.
- **Risk:** low. All three fixes make previously-MISLEADING output honest; none
  change what a command does to the filesystem, the gate, or the render. The
  only behavior CHANGE that an automation harness could observe is the exec
  family's exit code: `vh-agent-harness exec <child>` now exits the CHILD's
  code instead of collapsing to 1 (defect 2) — this is the fix, but any script
  that asserted "exec exits 1 on any child failure" needs to assert the real
  child code instead.

## Why this release exists
An operator migration (vh-solara, 2026-08-06) hit three compounded
output-honesty defects at once: the backlog normalizer's `--check` claimed a
write it never made (defect 1), the exec family collapsed every child exit
code to 1 (defect 2), and the exec family dumped a Usage/Flags block on a
legitimate child failure (defect 3). The three compounded — an operator saw a
Usage dump wrapped around a message claiming a write, and had to
reverse-engineer which parts were real. This release fixes all three as clean,
independent changes.

## What changed (consumer-visible only)
| area | change | ships-via | class |
|------|--------|-----------|-------|
| **backlog normalizer: `--check` no longer claims a normalization happened** | `renderSummary` opened with `Normalized backlog at <path>` unconditionally. In check mode (`--check`) the script writes NOTHING, yet printed that line — a false mutation claim about the shared ledger. The first line is now MODE-GATED: check mode says `Backlog normalization check (<path>)` and reports whether a cleanup is required / up-to-date; write mode keeps `Normalized backlog at <path>` unchanged. The rest of the summary (counts, archive, pending updates) is mode-independent and untouched. | `templates/core/.opencode/scripts/normalize-backlog.js` (embed source; rendered twin at `.opencode/scripts/normalize-backlog.js`, `platform_managed`) | non-breaking (wording-only; no behavior, exit code, or file-write change) |
| **exec family: child exit code propagated instead of collapsed to 1** | `vh-agent-harness exec bash -c 'exit 3'` exited 1: the `*exec.ExitError` from the runtime reached `Execute()` via the RunE return, but `Execute()` collapsed every error to `os.Exit(1)`. The real code survived only as text in `Error: exit status N`. A central exit-code extractor (`exitCodeFromError`) now propagates the real child code for `exec`, `exec-ro`, and `shell` (the three RunE handlers that return `be.Exec`'s error up through cobra). `exec-sandbox` was already correct (it calls `os.Exit(code)` directly and bypasses cobra). The extractor fires ONLY on a child-exit-code-bearing error (`*exec.ExitError` via `errors.As`, which traverses cobra's wrapping); `errSilent` and all other 1-exits are untouched. | binary self-update (Go source in `internal/cli/root.go`; not a rendered file) | behavior CHANGE (exit code now reflects the child; scripts asserting `==1` on any child failure must assert the real child code) |
| **exec family: no Usage/Flags dump on a child failure** | The exec family (`exec`, `exec-ro`, `exec-sandbox`, `shell`) was the ONLY command group missing `SilenceUsage: true` (the other 26 command definitions across `internal/cli/` all set it). On a child failure cobra printed `Error: exit status N` followed by the full Usage block, implying the operator mis-invoked the command. All four exec-family commands now set `SilenceUsage: true`. `SilenceErrors` is intentionally NOT set: genuine errors (permission denials, hook failures, child exits) still surface via cobra's single `Error:` line. | binary self-update (Go source in `internal/cli/exec_shell.go`, `exec_ro.go`, `exec_sandbox.go`; not rendered files) | non-breaking (a child failure no longer prints a misleading Usage block; the error line itself is preserved) |

## How to migrate (automated)
For every adopter: nothing beyond the standard re-render + binary self-update.
No data migration; no manual step.

```bash
vh-agent-harness self-update            # pull the new binary (v0.22.2)
vh-agent-harness version                # expect: 0.22.2 (<label>)
vh-agent-harness update --dry-run       # ownership-safe preview of the re-render
vh-agent-harness update                 # applies platform_managed + active overlay_extension
vh-agent-harness doctor                 # lint the result
```

If an automation script asserted `vh-agent-harness exec <child>` exits 1 on any
child failure, update it to assert the child's real exit code instead (defect 2).
This is the fix making output honest: the child's code was always the correct
thing to assert, but the collapse had hidden it.

## What `update` handles for you
- Re-renders `.opencode/scripts/normalize-backlog.js` from the fixed embed
  source (`platform_managed`, overwritten on every `update`). The next
  `--check` run prints `Backlog normalization check (<path>)` instead of the
  false `Normalized backlog at <path>` claim.

## Watch-outs
1. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers
   rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the
   binary first), NEVER a bare `vh-agent-harness update` — the stale-embed guard
   refuses a live `update` when the embedded corpus differs from
   `templates/core/`.
2. **The exec exit-code change is observable to automation.** Defect 2 is the
   one fix that changes an observable contract (exit code). A CI step or hook
   that previously branched on "exec exited 1" now sees the real child code.
   This is the intended honesty fix; update any such assertion.
3. **`exec-sandbox` exit handling is unchanged.** Defect 2's scope deliberately
   excluded `exec-sandbox` — its two-stage re-exec trampoline already called
   `os.Exit(code)` directly and never went through the cobra collapse. The
   `SilenceUsage` addition (defect 3) is the only exec-sandbox change, and it
   matters only on exec-sandbox's non-`os.Exit` error returns.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.22.1`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible state.
Rolling back restores the three defects: `--check` once again falsely claims a
normalization, the exec family once again collapses child exit codes to 1, and
the exec family once again dumps Usage on a child failure. The exit-code
rollback is the only one a script could depend on (incorrectly) — re-audit any
automation that started asserting the real child code before relying on a
rollback.

## Non-consumer changes
Supporting work in this arc that does not ship to consumers (lives outside the
consumer-visible `templates/core/` embed, or is test only): the Go-source
central exit-code extractor and the four `SilenceUsage` additions
(`internal/cli/root.go`, `exec_shell.go`, `exec_ro.go`, `exec_sandbox.go`); the
unit-level defect-2 guard (`internal/cli/exec_exit_code_test.go`, covering
`exitCodeFromError` logic + `errSilent` preservation + `%w`-chain traversal);
the end-to-end defect-2/3 crux (`tests/integration/exec_exit_code_test.go`,
building the real binary and asserting real `$?` + no Usage dump); and the two
black-box defect-1 wording tests appended to
`tests/scripts/normalize-backlog.test.js`.
