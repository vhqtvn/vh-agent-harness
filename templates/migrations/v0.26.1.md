# Migration: v0.26.1

## Summary
- **Release class:** PATCH (semver compatible). Since `v0.26.0`: 2 `fix:` commits,
  0 `feat:` commits, no `BREAKING CHANGE:` footers, no `<type:!>` subjects (10
  commits total; the dead-grant lint pair and the comment tidy ride as
  non-`feat`-typed defect-surfacing work). Under conventional-commit semver the
  honest bump is `v0.26.0` → `v0.26.1`. This is a defect-fix release driven by a
  downstream adopter report (TrueAI, harness 0.26.0) blocked on the F3
  ready→ready envelope validation fix and the inter-layer dead-grant lint.
  Last tag = `v0.26.0`; intended version = `v0.26.1`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for all adopters — no adoption-migration or one-time reconciliation
  this release.
- **Risk:** low for correctness (fixes + integrity surfacing only; nothing is
  removed or retracted), with ONE operational heads-up every upgrader must
  read: the new doctor `dead-grants` check can turn a previously-HEALTHY
  install UNHEALTHY where pre-existing dead allow/ask grants are present —
  that is the intended integrity surfacing of a pre-existing (previously
  silent) misconfiguration, not a regression. See Watch-outs 1–3.

## Watch-outs
1. **`dead-grants` is a hard gate, not advice.** Dead `allow` and dead `ask`
   grants = doctor FAIL → UNHEALTHY → non-zero exit → blocks release
   ceremonies like G0c. Redundant dead `deny`-only findings are non-failing
   INFO; zero findings is a quiet PASS.
2. **Upgraders with pre-existing dead allow/ask grants go UNHEALTHY —
   intended, not a regression.** Those grants were silently broken before this
   release; the upgrade surfaces them. The same `update` run that ships the
   check prints a non-blocking WARN naming each finding. Remediation paths in
   every message: remove the grant, downgrade the grant, or route through
   `vh-agent-harness exec` where the verb family is supported.
3. **There is deliberately NO project-declared engine-allow seam.** No overlay
   or profile field can add engine allowlist entries; a security-sensitive
   feature request for such a seam is tracked separately and is NOT in this
   release. Wrapper deny-time naming is static and adopter-neutral — it never
   attributes a deny to an active agent.
4. **F3 envelope validation now covers ready→ready refreshes.** Adopters using
   created-as-ready task cards now need a legitimate envelope at dispatch-time
   refresh: malformed, named-but-unresolved, or stale-digest envelopes are
   refused (nothing persisted) with structured F3 reasons; complete
   current-digest envelope refreshes still succeed; refreshes that do not
   supply an envelope remain exempt. This closes the structural
   injected-envelope bypass — it does NOT detect authorship forgery.
5. **Source-checkout repos (this dev/dogfood repo).** Source-checkout
   consumers rebuilding locally MUST use `make update` (the `Makefile` target
   rebuilds the binary first), NEVER a bare `vh-agent-harness update` — the
   stale-embed guard refuses a live `update` when the embedded corpus differs
   from `templates/core/`. Same for `doctor`: use `make doctor` in a source
   checkout.
6. **The commit-gate fix changes lock-failure vocabulary.** Automation that
   string-matched the old contended/`race_lost` classification for genuinely
   unavailable lock paths should now expect `lock_dir_unavailable` /
   `gate_index_dir_unavailable` (genuine concurrent contention still reports
   `race_lost`). Main-checkout behavior is byte-equivalent.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.26.0`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible
state. Rolling back re-hides dead allow/ask grants (doctor has no #27 in
0.26.0, so previously-silent misconfigurations go quiet again — the grants
remain broken), reopens the F3 ready→ready injected-envelope bypass (supplied
envelopes are again stored unvalidated), returns wrapper denies to their plain
form (no grant naming), and reintroduces the linked-worktree ENOTDIR masking
as `race_lost`. Refusals issued by the v0.26.1 validators never mutate task
state, so no cleanup is needed before downgrading.
