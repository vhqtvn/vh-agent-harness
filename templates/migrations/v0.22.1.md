# Migration: v0.22.1

## Summary
- **Release class:** PATCH (semver compatible). One `fix:` since `v0.22.0`,
  zero `feat:`/`!:`/`BREAKING CHANGE:`. No shipped contract, capability,
  profile, ownership class, or API surface changes — this is a narrow
  release-tooling bug-fix. Last tag = `v0.22.0`; intended version = `v0.22.1`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Fully automatic; no manual migration step is required for any adopter.
- **Risk:** low. The fix is confined to the release-evaluator
  (`check-defer-triggers.mjs`, a promoter/operator-use-only script). It does
  not change any behavior a running agent session, a commit gate, or a render
  depends on for correctness. The only observable difference is that the
  release-evaluator's stdout no longer truncates under a slow pipe reader.

## Why v0.22.1 exists (forward-only successor to a half-finished v0.22.0)
`v0.22.0` was left half-finished: this fix (`615e7be`) landed ON TOP OF
`v0.22.0`'s manifest commit, and a follow-up re-pinned `v0.22.0`'s manifest
handshake to include the fix — but the intended "move the `v0.22.0` tag forward
to the re-pinned manifest" was never executed. Completing the tag-move now is
disallowed: `v0.22.0` is already **published to origin**, the sanctioned
`scripts/release-tag.sh` wrapper has no force/move mode (it refuses "tag already
exists"), and a force-move of a published tag is a harmful rewrite (Go
proxy/sumdb entries are immutable; goreleaser release surgery). The safe path is
forward-only: cut `v0.22.1` on top of current HEAD so the release-evaluator fix
ships under a correct, fresh manifest. `v0.22.0` is left exactly where it is.

## What changed (consumer-visible only)
| area | change | ships-via | class |
|------|--------|-----------|-------|
| **release-evaluator: flush stdout before exit** | `check-defer-triggers.mjs` emitted its JSON result with `process.stdout.write(...)` immediately followed by `process.exit(code)`. Under a slow pipe reader (release CI's `| tee` step) the write partial-flushed at the 64 KiB kernel pipe buffer and `exit()` discarded the remainder, so CI failed with `Unterminated string in JSON`. Fast readers (`>` redirection, `spawnSync`) drained synchronously and were green, hiding the bug. The fix defers `process.exit(code)` into the write drain callback in both `emitReleaseResult` and `emitReleasePrepResult`. | `templates/core/.opencode/scripts/check-defer-triggers.mjs` (embed source; rendered twin at `.opencode/scripts/check-defer-triggers.mjs`, `platform_managed`) | non-breaking (release-tooling internal; no agent/gate/render consumer depends on the truncated path) |

## How to migrate (automated)
For every adopter: nothing beyond the standard re-render. This release touches
only a promoter/operator-use-only script; no agent session, commit gate, or
render consumes the changed path for correctness.

```bash
vh-agent-harness self-update            # pull the new binary (v0.22.1)
vh-agent-harness version                # expect: 0.22.1 (<label>)
vh-agent-harness update --dry-run       # ownership-safe preview of the re-render
vh-agent-harness update                 # applies platform_managed + active overlay_extension
vh-agent-harness doctor                 # lint the result
```

## What `update` handles for you
- Re-renders `.opencode/scripts/check-defer-triggers.mjs` from the fixed embed
  source (`platform_managed`, overwritten on every `update`). The next release
  ceremony's release-evaluator output is now byte-complete under any pipe
  reader, including CI's `| tee`.

## Watch-outs
1. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers
   rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the
   binary first), NEVER a bare `vh-agent-harness update` — the stale-embed guard
   refuses a live `update` when the embedded corpus differs from
   `templates/core/`.
2. **`v0.22.0` is unchanged.** This release does NOT move, force, or delete the
   published `v0.22.0` tag. Adopters who already updated to `v0.22.0` are on a
   valid release; `v0.22.1` is simply the forward successor that ships the
   release-evaluator stdout fix.
3. **The fix is promoter/operator-facing, not agent-facing.** An agent session
   never invokes `check-defer-triggers.mjs` directly for its own correctness;
   the script is the release-ceremony DEFER evaluator. The only behavioral
   change is the absence of pipe-truncation during a release.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.22.0`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible state.
Rolling back restores the pre-fix release-evaluator, so a release ceremony run
through a slow pipe reader could once again truncate at 64 KiB — the symptom is a
`Unterminated string in JSON` error in CI, not silent corruption.

## Non-consumer changes
Supporting work in this arc that does not ship to consumers (lives outside the
consumer-visible `templates/core/` embed, or is bookkeeping): the 4-case black-box
regression `tests/scripts/check-defer-triggers.test.js` (mirrors CI's exact
`bash -o pipefail ... | tee` shape with a > 64 KiB payload); the auto-regenerated
content-hash bookkeeping (`.vh-agent-harness/lineage.yml`,
`.vh-agent-harness/rendered-outputs.json`); and the ceremony commit
`59a9264 chore(release): v0.22.0 manifest re-pin` (bookkeeping from the
abandoned v0.22.0 tag-move attempt, excluded from the changelog by goreleaser's
`^chore:` filter). The single DEFER card this arc surfaced
(`defer-trigger-checker-distinguish-nonfiring-from-hold`, which fired only
because the fix touched the evaluator's embed source) is orthogonal to the fix
— it concerns the checker's *display* of never-firing cards — and is disposed
`disclose / release_relevance:no` (non-blocking) in this release's manifest.
