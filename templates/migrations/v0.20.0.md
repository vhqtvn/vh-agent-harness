# Migration: v0.20.0

## Summary
- **Release class:** MINOR (semver compatible). The `v0.19.0..HEAD` arc (61
  commits) is an **additive feature** release dominated by the declared-scope
  coverage validator (F4-A) with the full/targeted/smoke + clean-transition +
  declared-scope green-distinction docs, two S1 overlay-skill pilots
  (`resolve-first` DEFER-processing and `formal-verification` agent-authored
  proofs), config-driven coordination product-prefixes, a `/task-delete`
  destructive single-card removal wrapper, `exec-ro`→`exec-sandbox` ladder
  guidance for denied read-only commands, a release-gate DEFER manifest scope
  widening (option b — every firing card gets an explicit disposition), and a
  release tag-pinning fix that closes the silent HEAD-drift re-targeting
  incident class. It carries **8 `feat`** commits, **7 `fix`** commits, **zero
  `!:` subjects**, and **no `BREAKING CHANGE:` footers** → MINOR bump; not patch
  (real consumer-facing behavioral additions across the embedded Go binary and
  the re-rendered corpus), not major (every edit is additive — no shipped
  contract, capability, or profile change is removed or renamed in a way that
  breaks a default consumer). No profile, ownership-class, capability, or
  runtime change is required; the default consumer's `opencode.jsonc` gains
  only the additive `docs-steward` delegate allowlist (a new permission grant,
  no removal/rename — non-breaking), re-rendered automatically by `update`.
  Last tag = `v0.19.0`;
  intended version = `v0.20.0`.
- **Upgrade path:** binary self-update, then re-render the corpus. Fully
  automatic for the default consumer. The declared-scope coverage validator, the
  `/task-delete` command, the `resolve-first` and `formal-verification` skills,
  the formal-verification engine-invocation config (unprovisioned default), the
  config-driven coordination product-prefixes, the `exec-ro` deny-footer ladder
  guidance, the release-gate DEFER manifest scope widening, and the release
  tag-pinning + releaser portability fixes ship in the embedded Go binary and/or
  the embedded corpus (re-rendered by `update`). `templates/core/` remains
  domain-free (token-only; no adopter/overlay identifier in any source or
  rendered file). Source-builders rebuilding from this tag are unaffected (no Go
  toolchain bump).
- **Risk:** low. Every change is additive. The formal-verification config ships
  **unprovisioned by default** (no engine is wired; it is an opt-in capacity
  that activates only when an operator provisions an engine), so it cannot
  change behavior today. The release-gate DEFER scope widening (option b) is
  non-blocking by default: every firing card now receives an explicit
  disposition (frequently a non-blocking `disclose`), and the release-mode gate
  refuses a tag only on a genuine release-blocking finding — dormant unless a
  release is imminent. The release tag-pinning fix (`cab169f`) closes the silent
  HEAD-drift re-targeting incident class (a tag is now pinned to the validated
  commit with an explicit commit argument, never bare HEAD; a concurrent landing
  during a ceremony is excluded and surfaced as `head_drift`, never silently
  re-targeting the tag).

- Re-renders `check-defer-triggers.mjs` carrying the widened (option b) DEFER manifest scope, and the releaser ceremony prompt carrying the tag-pinning + genericized (F5-portable) decision-memo path.
- Re-renders the permission config granting `docs-steward` delegate to `coordination` + `project-coordinator`, and `commit-gate.sh` carrying the acquire-time meta-sweep alignment.

## Watch-outs
1. **The formal-verification config is unprovisioned by default.** The `formal-verification` skill + engine-invocation config ship as structure, but NO engine is wired. The capacity cannot change behavior until an operator provisions an engine; it never gates commits, releases, doctor, or updates.
2. **The release-gate DEFER scope widening is non-blocking by default.** Every firing card now gets an explicit disposition (frequently a non-blocking `disclose`); the release-mode gate refuses a tag only on a genuine release-blocking finding. Repos with no release-blocking findings (the common case) are unaffected. When the Go defer-liveness gate refuses mid-ceremony (a firing card with no closed status, no manifest entry, and no override), the non-destructive escape hatch is the `VH_HARNESS_DEFER_OVERRIDE_IDS` env var — do NOT `rm` transport cards to clear the gate (`rm` is the sanctioned retire path for a genuinely-done card, not a ceremony unblock).
3. **Release tag-pinning (`cab169f`) — operators cutting releases.** A release tag is now pinned to the validated commit with an explicit commit argument, never bare HEAD. A concurrent commit landing during a ceremony is excluded from that release and surfaced as `head_drift: true` (the release itself is correct and MUST NOT be rolled back for drift alone; the concurrent commit lands in the next release).
4. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the binary first), NEVER a bare `vh-agent-harness update` — a bare update would silently overwrite in-progress `.opencode/` work with a stale embedded corpus (the stale-embed guard refuses a live `update` when the embedded corpus differs from `templates/core/`). GoReleaser rebuilds for the published artifact regardless.
5. **DEFER state at this release.** The release-mode DEFER scan for the `v0.19.0..HEAD` arc shows no release-blocking findings (all firing cards classify `disclose`; `blocking_ids` empty). The widen-manifest (option b) change means every firing card now receives an explicit committed disposition; the manifest content for the `v0.20.0` arc is promoter-curated.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness` binary (e.g. `v0.19.0`), then `vh-agent-harness update` to re-render the corpus from that binary's embedded corpus. No data migration; no irreversible state. The declared-scope coverage validator, the `/task-delete` command, the two S1 overlay skills, the formal-verification config, the config-driven product-prefixes, the `exec-ro` ladder guidance, the release-gate DEFER scope widening, and the release tag-pinning/portability fixes are all additive — a prior binary simply does not exercise them, and re-rendering from a prior binary's corpus restores the prior scripts. Source-checkout consumers rolling back MUST use `make update` against the prior tag (the `Makefile` target rebuilds first), not a bare `update`.
