# Migration: v0.31.0

## Summary
- **Release class:** MINOR (operator-directed). The arc's conventional-commit
  composition is PATCH-class — 15 commits since `v0.30.0`: 0 `feat:`, 2
  `fix:`, 9 `docs:`, 4 `test:`; no `!:` subjects and no `BREAKING CHANGE:`
  footers — and the minor bump is the operator's release-cadence choice for
  this arc (readiness G2 green; G2 blocks only breaking-as-patch, which this
  arc is not). Disclosed here so the version number is never misread as a
  feature-signal: this release ships NO new harness capability and NO binary
  behavior change.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for all adopters. No adoption-migration, no one-time
  reconciliation, no ownership/schema/profile action this release.
- **Risk:** low. Zero Go/binary behavior changes in the entire arc — the only
  consumer-visible delta is re-rendered command/template prose (the
  `/task-repair` command template and the AGENTS core gloss), which `update`
  applies mechanically.

The central thing to understand about this release: it is a
**docs-and-fixes stability release**. The one behavioral fix is confined to
the rendered `/task-repair` command (its restage route now invokes the right
plan-state operation per card state — `f935c1d`); the one consumer-relevant
docs change aligns that command's prose with its three-route reality
(`1f4d2c2`). Everything else is repo-local: release-gate hardening and test
pins (dogfood-only surfaces) and checkpoint record-keeping.

## How to migrate (automated)
```bash
vh-agent-harness self-update            # pull the new binary (v0.31.0)
vh-agent-harness version                # expect: 0.31.0 (<label>)

```
No profile, ownership-class, capability, or schema action is required.
Restart opencode after `update` so the changed command doc and the composed
AGENTS.md load into new sessions.

## Rollback
A minor release with no data migration is reversible by binary downgrade +
re-render: reinstall the `v0.30.0` binary and `vh-agent-harness update`
(source-checkout repos: `make update` against the prior tag). **Caveats:**
(a) the corpus reverts with it — the corrected `/task-repair` restage routing
and the three-route prose disappear (the pre-v0.31.0 dead-end returns);
(b) origin-hash ledger entries advanced by v0.31.0's `update` are repo-local
preserved state — under the older binary they may surface as managed-drift;
that is the ledger honestly reporting the downgrade, not a defect. No other
state to undo.
