# Migration: v0.24.0

## Summary
- **Release class:** MINOR (semver compatible). 17 `feat:` commits plus 20 `fix:`
  commits since `v0.23.0`; no `BREAKING CHANGE:` footers, no `<type>!:` subjects.
  Last tag = `v0.23.0`; intended version = `v0.24.0`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for new installs and for adopters already carrying a prior
  origin-hash sidecar. Existing v0.23.0 adopters WITHOUT a sidecar hit a
  one-time preserve/stall reconciliation on the first update (the origin-hash
  adoption migration classifies their unknown baseline and stalls rather than
  silently overwriting); after that one-time reconciliation it is automatic on
  every subsequent update.
- **Risk:** low. The headline additions (private redlines, rewrite-parity contract
  gate, origin-hash adoption migration, repo-scoped pause-on-new-work) are
  additive safety/correctness surfaces. The origin-hash adoption migration is the
  one change an existing v0.23.0 adopter's FIRST update after installing v0.24.0
  will observe: it classifies an unknown baseline (no prior origin-hash sidecar)
  and preserve/stalls rather than silently overwriting. The chunk-timeout-backstop
  config-hook is additive and dormant until configured. No shipped contract,
  capability, profile, or API surface has a breaking change.

## Why this release exists
This release ships four consumer-facing safety/correctness pillars that were
developed across the v0.23.0→v0.24.0 arc:

1. **Private redlines** — a machine-local deny-list registry that scans agent
   output and gates commits. Lets an operator enforce "never emit / never
   commit" patterns (secrets, paths, phrases) without touching shared config.
2. **Origin-hash adoption migration** — the update path now distinguishes an
   unknown baseline (a consumer repo with no prior origin-hash sidecar) from a
   known one, and preserve/stalls unknown-baseline files rather than silently
   overwriting them. Closes the "first update after install silently clobbers
   local edits" failure class. A three-way update sync then preserves consumer
   edits on every subsequent update.
3. **Rewrite-parity contract gate** — an explicitly-declared deletion or rewrite
   slice now carries a two-stage hybrid contract (commit-gate mechanical
   precheck + closeout structural-completeness gate). Ordinary deletes/refactors
   carry zero rewrite-parity burden; the contract is opt-in.
4. **Repo-scoped pause-on-new-work** — the dispatch seams now honor a repo-scoped
   pause signal so an in-flight coordination context is not silently interrupted
   by new work landing in the same repo.

Plus: a deterministic G6 S2-hold gate on the release-tag wrapper, an
RF-B structural file-authoring deny in shell-guard (file authoring is now denied
BEFORE the forbidden-pattern scan, not after), a doctor closeout-reach
reconciliation (#24) that catches orphaned closeout-ledger entries, permission
hardening (git merge-base/rev-list allow + mutation-deny surface), and an exec
sanctioned-alternative footer at deny friction points.

## How to migrate (automated)
For new installs and adopters already carrying a prior origin-hash sidecar:
nothing beyond the standard re-render + binary self-update. For existing v0.23.0
adopters WITHOUT a sidecar, the first update hits a one-time preserve/stall
reconciliation (the origin-hash adoption migration); reconcile each stalled path
once, then every subsequent update is automatic.

```bash
vh-agent-harness self-update            # pull the new binary (v0.24.0)
vh-agent-harness version                # expect: 0.24.0 (<label>)
vh-agent-harness update --dry-run       # ownership-safe preview of the re-render
vh-agent-harness update                 # applies platform_managed + active overlay_extension
vh-agent-harness doctor                 # lint the result
```

If the origin-hash adoption migration preserve/stalls any file, `update` names
the preserved/stalled paths in its output. Reconcile each once (accept the
platform version with `accept-platform`, or keep your local edit), then re-run
`doctor`.

## What `update` handles for you
- Renders the private-redline scan/gate wiring into `.opencode/` so the
  machine-local redline registry is active after the update.
- Renders the rewrite-parity contract-gate precheck into
  `.opencode/scripts/commit-gate.sh` so the two-stage hybrid gate is enforced
  on every explicitly-declared deletion/rewrite slice.
- Renders the F2 transient-locator reject gate and the land-gate
  completed-card-retirement rule into the coordination lifecycle.
- Renders the permission rule updates (git merge-base/rev-list allow,
  mutation-deny hardening, RF-B structural file-authoring deny ordering).
- Renders the contained defer-triggers wrapper for read-only roles.

## Watch-outs
1. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers
   rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the
   binary first), NEVER a bare `vh-agent-harness update` — the stale-embed guard
   refuses a live `update` when the embedded corpus differs from
   `templates/core/`.
2. **Origin-hash adoption migration is observable on the FIRST update.** A
   consumer repo with no prior origin-hash sidecar will see unknown-baseline
   `platform_managed` files preserve/stalled for one-time reconciliation. This
   is the intended safety behavior (prevent silent overwrite); reconcile each
   stalled path once via `accept-platform` or by keeping your local edit.
3. **The rewrite-parity contract is opt-in.** Ordinary deletes, refactors,
   renames, and reorganization carry ZERO rewrite-parity burden. The contract
   applies ONLY when a task declares `mode: deletion_replacement` or
   `mode: modification_only_rewrite`. Do not add a contract to an ordinary
   refactor.
4. **Private redlines are machine-local.** A redline does NOT travel in shared
   config or overlays — it is a machine-local deny pattern. This is by design
   (an operator enforces local policy without modifying `templates/core/`), but
   it means redlines do not propagate to other machines or repos.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.23.0`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible state.
Rolling back removes the private-redline surface, the rewrite-parity contract
gate, the origin-hash adoption migration, and the repo-scoped pause-on-new-work
behavior. If the adoption migration preserve/stalled any file before rollback,
reconcile or discard those stalled paths before rolling back so the prior
binary's update does not re-process them.
