# Migration: v0.25.0

## Summary
- **Release class:** MINOR (semver compatible). 2 `feat:` commits (F8 batch
  accept-platform, F2-narrow agents-composition doctor check) plus 3 `fix:`
  commits since `v0.24.0`; no `BREAKING CHANGE:` footers, no `<type>!:` subjects.
  Under conventional-commit semver, features in a `0.x` series bump MINOR, so the
  honest bump is `v0.24.0` → `v0.25.0`. Last tag = `v0.24.0`; intended version =
  `v0.25.0`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for all adopters — no adoption-migration or one-time reconciliation
  this release (the origin-hash adoption migration landed in v0.24.0 and is now
  steady-state).
- **Risk:** low. The headline changes are a closed-trap fix (F1 shell-guard
  over-match that blocked sanctioned recovery verbs), an integrity fix (F3
  commit-gate GC reaping in-use protected files under contention), a batch
  migration unblocker (F8 accept-platform --all/--stale-only), a defense-in-depth
  doctor check (F2-narrow agents-composition WARN), and a display-clarification
  wording pass (F7 drifted-vs-render). No shipped contract, capability, profile,
  or API surface has a breaking change.

## How to migrate (automated)
```bash
vh-agent-harness self-update            # pull the new binary (v0.25.0)
vh-agent-harness version                # expect: 0.25.0 (<label>)
vh-agent-harness update --dry-run       # ownership-safe preview of the re-render
vh-agent-harness update                 # applies platform_managed + active overlay_extension
vh-agent-harness doctor                 # lint the result
```
No adoption-migration reconciliation this release. If you have stalled paths from
the v0.24.0 origin-hash adoption migration, the new `accept-platform --all` (or
`--stale-only`) recovers them in one invocation instead of one path at a time.

## What `update` handles for you
- Renders the F1 shell-guard carve-out into the consumer shell-guard rules so
  `accept-platform`/`diff` on `commit-gate.sh` paths are no longer over-blocked.
- Renders the F3 commit-gate `_file_age_seconds` stat-fallback fix into
  `.opencode/scripts/commit-gate.sh` so the GC retains protected scratch on stat
  failure.
- Renders the F6 scoped test-reference comments in `verify-task-registry.js` and
  the F5-narrow refreshed `RECORD_LIFECYCLE.md` prose.

## Watch-outs
1. **Source-checkout repos (this dev/dogfood repo).** Source-checkout consumers
   rebuilding locally MUST use `make update` (the `Makefile` target rebuilds the
   binary first), NEVER a bare `vh-agent-harness update` — the stale-embed guard
   refuses a live `update` when the embedded corpus differs from
   `templates/core/`. The same mechanism applies to `doctor`: in a
   source-checkout repo, bare `vh-agent-harness doctor` may resolve to a stale
   PATH binary and report a false UNHEALTHY (the documented `dev-stale-embed`
   trap); `make doctor` (Makefile target rebuilds first) is the canonical form.
   Consumers whose binary embeds the same corpus they run with are unaffected.
2. **F3 is a concurrency-safety fix, not a behavior change.** The happy path
   (successful `stat` → correct age) is unchanged; only the transient-failure
   fallback changed (`echo 0` → `echo "$now"`). No configuration or workflow
   change is required.
3. **F2-narrow agents-composition is WARN-only.** It NEVER makes the repo
   UNHEALTHY. If you have NOT adopted the core/mission split (no
   `.vh-agent-harness/AGENTS.mission.md`), the check SKIPs. If you have, re-run
   `vh-agent-harness update` to re-compose the root `AGENTS.md` and clear the
   WARN.
4. **F8 accept-platform is destructive-by-intent.** `--all` and `--stale-only`
   adopt the platform bytes for each selected path (overwriting consumer
   edits whose live bytes differ from the render). This is the same semantics as
   the per-path positional form, just batched. Always preview with
   `vh-agent-harness diff` first if unsure.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.24.0`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible state.
Rolling back removes the F1 carve-out (re-introducing the shell-guard over-block
on `commit-gate.sh` paths), the F3 stat-fallback fix (re-introducing the
contention reap risk), the F8 batch flags, the F2-narrow doctor check, and the
F7 display qualification. If you used `accept-platform --all` to recover stalled
paths before rolling back, those paths are already at platform bytes and need no
further reconciliation.
