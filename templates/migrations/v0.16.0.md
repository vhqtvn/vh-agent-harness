# Migration: v0.16.0

## Summary
- **Release class:** MINOR (semver compatible). The `v0.15.1..HEAD` arc (46
  commits) is a **multi-area feature release** spanning the operator-visibility
  initiative: the F1 synthesis-envelope CLI, the F2 rendering family, the F3
  design-readiness system, the behavioral-closure pilot, the dev-stale-embed
  guard, coordinator defer-liveness hardening, memory identity hardening, and
  bounded help/migration forward-path. The arc carries **24 `feat` commits**,
  **3 `fix` commits**, **zero `!:` subjects**, and **no `BREAKING CHANGE:`
  footers** → MINOR bump; not patch/major. Every consumer-visible change is
  additive/opt-in: the default consumer's `opencode.jsonc` is byte-identical
  unless they select the new capabilities, and every new `doctor` check is
  inert unless its trigger conditions exist. Last tag = `v0.15.1`; intended
  version = `v0.16.0`.
- **Upgrade path:** binary self-update, then re-render the corpus. Fully
  automatic for the default consumer. All feature areas ship in the Go binary
  (CLI commands + doctor checks) and/or the embedded corpus (re-rendered by
  `update`). No profile, ownership-class, capability, or runtime change is
  required. `templates/core/` remains domain-free (token-only). Source-builders
  rebuilding from this tag are unaffected (no Go toolchain bump).
- **Risk:** low. Every new gate/doctor check is fail-closed by design — it can
  only SKIP or refuse a release tag, never force one. The dev-stale-embed guard
  is the one behaviorally active change for source-checkout consumers (it
  refuses `update` on a divergent source tree), but only affects repos that
  carry BOTH `corpus.go` and `templates/core/` at their root (i.e. this
  dev/dogfood repo, not downstream consumers). Greenfield repos keep their
  exact pre-v0.16.0 behavior across every new check.

## Watch-outs
1. **dev-stale-embed guard is behaviorally active for source checkouts.** A repo
   carrying BOTH `corpus.go` and `templates/core/` at its root will have a bare
   `vh-agent-harness update` REFUSED when the binary's embedded corpus differs
   from the on-disk `templates/core/`. Use `make update` (the `Makefile` target
   rebuilds first). `--allow-stale-corpus` is the explicit override. This guard
   never fires on consumer repos (they lack `corpus.go`).
2. **The dev-stale-embed WARN alone never makes doctor UNHEALTHY.** Doctor
   surfaces a non-failing WARN and qualifies its `managed-drift` line. The WARN
   is informational; only the live `update` refusal is enforced.
3. **Doctor check #14 (behavioral-closure) is a declaration-consistency gate,
   not a proof gate.** The token makes a closeout declaration non-droppable and
   internally consistent; it does NOT prove the cited crux path executed.
   Proving the crux needs the repo-specific live verification (the verified
   seam). An internally-inconsistent token (e.g. `verdict: proven` without
   `result: proven`) FAILs; a consistent-but-unverified token passes #14 but
   may still be caught by the verified seam.
4. **Doctor check #18 (F2 pair-consistency) is inert unless F2 pairs exist.**
   It audits every F2 structural pair for consistency. Greenfield repos with no
   F2 outputs see a SKIP.
5. **The §4.3 defer-liveness channel-liveness tradeoff (Option A).** The
   coordinator-adoption marker closes WHOLE-DIR loss
   (`.local/coordinator/tasks/` deleted) but NOT selective single-card
   deletion. Whole-dir loss is the structurally-forced gitignore vector;
   single-card deletion is accepted because an actor who can delete a card can
   also delete the committed marker.
6. **The marker is the opt-in, not `.local/`.** The gate does NOT infer adoption
   from `.local/coordinator/tasks/` presence (losable transport). Only the
   committed marker counts. A repo with transport present but no marker SKIPs.
7. **Greenfield stays green.** A fresh install keeps the exact pre-v0.16.0 SKIP
   behavior across all new checks (#12 marker absent→SKIP, #14 no token→SKIP,
   #18 no pairs→SKIP). Do not pre-create the marker by hand.
8. **F1/F2/F3 are pure, additive CLI surfaces.** They add new producers,
   validators, and gates without changing any existing command's behavior. They
   are invoked explicitly; the default consumer never triggers them unless they
   adopt the F2 rendering workflow or the F3 BUILD-READY ceremony.

## Rollback
A minor release is reversible by binary downgrade: reinstall the `v0.15.1`
binary and `vh-agent-harness update` re-renders the `v0.15.1` corpus. **Caveats:**
rolling back (a) removes the F1/F2/F3 CLI surfaces, the behavioral-closure
pilot, and doctor checks #14/#18; (b) removes the dev-stale-embed guard — a
bare `update` no longer refuses on a divergent source checkout; (c) restores the
unconditional `if !reg.TasksPresent { tierSkip }` behavior in doctor check #12 —
the §4.3 fail-open returns; (d) re-renders the older `.opencode/scripts/state-lib.js`
without the marker producer or the unrendered-scripts guard; (e) does NOT delete
any committed `.vh-agent-harness/coordinator-adoption.json` — the file is
unmanaged and survives, but the v0.15.1 binary does not consult it; (f) reverts
the memory identity hardening. No data migration ran, so there is nothing to
undo beyond the binary reinstall and re-render. A `local_adopted` customization
survives the rollback as before.
