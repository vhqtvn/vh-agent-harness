# Migration: v0.26.0

## Summary
- **Release class:** MINOR (semver compatible). 1 `feat:` commit (doctor
  interaction-reachability crux enforcement + the `frontend-ui-pilot` overlay
  pack) and 1 `fix:` commit (substrate nil-Reconciler panic in armed-merge
  re-derive) since `v0.25.0`; no `BREAKING CHANGE:` footers, no `<type>!:`
  subjects. Under conventional-commit semver the honest bump is `v0.25.0` →
  `v0.26.0`. Last tag = `v0.25.0`; intended version = `v0.26.0`.
- **Upgrade path:** binary self-update, then re-render the corpus
  (`vh-agent-harness update`; source-checkout repos MUST use `make update`).
  Automatic for all adopters — no adoption-migration or one-time reconciliation
  this release.
- **Risk:** low. The headline changes are a new defense-in-depth doctor gate
  (fires ONLY on closeouts that declare `interaction_touching: true`; absent or
  `false` declarations trigger no checks), a correctness fix for a
  crash-on-unregistered-path class, an opt-in advisory overlay pack (not
  selected by default), and corpus documentation prose. No shipped contract,
  capability, profile, or API surface has a breaking change.

## How to migrate (automated)
```bash
vh-agent-harness self-update            # pull the new binary (v0.26.0)
vh-agent-harness version                # expect: 0.26.0 (<label>)
vh-agent-harness update --dry-run       # ownership-safe preview of the re-render
vh-agent-harness update                 # applies platform_managed + active overlay_extension
vh-agent-harness doctor                 # lint the result
```
No adoption-migration reconciliation this release. The only behavioral
attention point: if your repo's closeout records declare
`interaction_touching: true`, they now need the six-field receipt (or doctor
check #14 FAILs); records without the predicate are unaffected. The
`frontend-ui-pilot` pack does nothing until you list it under `overlays:`.

## What `update` handles for you
- Renders the six-field interaction-reachability receipt authoring spec into
  consumer `AGENTS.core.md` (composed into root `AGENTS.md` where the
  core/mission split is adopted), `CLOSEOUT_TEMPLATE.md`, and the
  `task-closeout` command.
- Renders the defer-triggers wrapper prose into
  `docs/coordination/README.md` (read-only roles use the contained
  `vh-agent-harness defer-triggers` wrapper).
- Does NOT enable `frontend-ui-pilot` — the pack renders only when listed
  under `overlays:` in `vh-harness-profile.yml`.

## Watch-outs
1. **Doctor #14 is a hard release gate, not advice.** A closeout declaring
   `interaction_touching: true` with a missing six-field receipt — or with
   `interaction_evidence: mechanism` paired with `result: proven` — FAILs
   doctor → UNHEALTHY → blocks release G0c. The check is dormant (no checks
   fire) when the predicate is absent or `false`, so pre-existing closeouts
   without interaction claims are unaffected.
2. **`frontend-ui-pilot` is opt-in and advisory-only.** It is not selected by
   default and adds zero enforcement; the `interaction-reachability` skill
   INFORMS the author/reviewer and may issue a DEFER — it never blocks,
   approves, or unblocks on its own. Core promotion is S2-held.
3. **Source-checkout repos (this dev/dogfood repo).** Source-checkout
   consumers rebuilding locally MUST use `make update` (the `Makefile` target
   rebuilds the binary first), NEVER a bare `vh-agent-harness update` — the
   stale-embed guard refuses a live `update` when the embedded corpus differs
   from `templates/core/`. Same for `doctor`: use `make doctor` in a source
   checkout. Consumers whose binary embeds the same corpus they run with are
   unaffected.
4. **The substrate fix is a crash fix, not a behavior change.** Registered
   `platform_armed` paths take the identical route as before; only the
   unregistered-path failure mode changed (SIGSEGV → typed `WriteFailed` +
   `ActionArmedProposal` downgrade). No configuration or workflow change is
   required.

## Rollback
Reversibility: binary downgrade + re-render. Install a prior `vh-agent-harness`
binary (e.g. `v0.25.0`), then `vh-agent-harness update` (source-checkout repos:
`make update` against the prior tag). No data migration; no irreversible
state. Rolling back removes the doctor #14 interaction-reachability
enforcement, the `frontend-ui-pilot` pack availability, the receipt authoring
spec, and the defer-triggers wrapper prose — and reintroduces the
unregistered-`platform_armed`-path panic in the substrate armed-merge
re-derive. Closeout records already written with six-field receipts remain
valid prose under the older binary (the older doctor simply does not check for
them).
