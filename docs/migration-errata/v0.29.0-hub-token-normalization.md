## What this notices, and why (grammar-only intent)

The hub script `state-lib.js` carried exactly one token that does not
conform to the frozen ESM grammar the platform's link checker (eslink)
enforces: an update operator (`i++`) in a for-update slot. The change is
**grammar-only in intent** — it exists so the hub module parses FIT under
that grammar and its import/export edges become link-checkable.
No behavior change is claimed, and none is verified by the gates.

At landing
(measured receipt: `researches/sources/2026-11-09-eslink-stage4-candidate-measurement.md`
@ `f2c3700`; decision record:
`researches/decisions/2026-11-09-eslink-o4-stage4-normalization-option2.md`),
the one-token normalization flipped the hub module to FIT with 73 named
exports and recovered the 22 hub-blocked edges (19 incoming + 3 outgoing),
raising enforceable L3 link coverage from 10/49 to 32/49 with broken
remaining 0.

## The exact change (one token)

- File: `templates/core/.opencode/scripts/state-lib.js`, line **5554** —
  the file's sole update-op, in the **for-update slot of `fnv1a32Hex`**
  (the expression value is unused in that slot).
- Diff: `for (let i = 0; i < s.length; i++) {` →
  `for (let i = 0; i < s.length; i += 1) {` — i.e. `i++` → `i += 1`.
- Commit: **`4469f3c`** (post-v0.29.0 corpus work; line-anchored, one
  production file).
- Semantic-preservation receipts recorded at landing: an old-vs-new runtime
  vector probe of `decisionItemId` across the changed `fnv1a32Hex` loop
  returned **40/40 identical outputs** (recorded in the `4469f3c` commit
  message), and `make test-js` was green at landing and re-verified green
  at notice authoring (**234/234**, `node --test tests/scripts/*.test.js`).

## Hub origin-hash advance

`state-lib.js` renders as `platform_managed` into **every** consumer repo —
the core renderer ships it unconditionally. The one-token change therefore
advances the hub's recorded origin hash; the ledger sync landed at commit
`0b56ab6` (`.vh-agent-harness/origin-hashes.json`). Consequence by adopter
state:

- **Unedited hub (the default):** nothing to do. The next `update` performs
  the normal `platform_managed` overwrite and your hub matches the corpus.
- **Preserved or locally-edited hub:** your file does NOT advance
  automatically — see the next section.

## If you preserved or edited state-lib.js (stale-preserve consequence)

On the first `update` that carries this corpus change, a preserved hub is a
both-moved path (your bytes diverged from the recorded origin AND the
platform's bytes changed since that origin). You will see, per the landed
surfacing:

- the update listing marks the path
  **`[consumer-edit, platform-also-changed]`** and appends the
  **stale-preserve warning** — the preserved file did NOT receive this
  update's platform changes; dependent runtime files or documentation
  updated by this release may no longer match it;
- `vh-agent-harness doctor` reports the path as **`preserved-stale-vs-corpus`
  at WARN** (non-failing — doctor stays HEALTHY).

This is surfacing only: preservation is intended behavior, and your edit is
never clobbered. For this specific one-token change the platform delta is a
single grammar-conformance token, but the stale-preserve state itself is
what matters — a preserved hub keeps falling behind every subsequent hub
change until reconciled.

## Reconciliation — safeguard first, then reconcile

Before anything else, **back up and diff your local edit**: byte-for-byte
backup of the live file (e.g. `cp <path> <path>.bak`) and inspect the delta
with `vh-agent-harness diff`. Only then reconcile:
`vh-agent-harness accept-platform <path>` (destructive-by-intent — it
writes platform bytes and advances the origin) and re-apply your edit, or
port the customization to a canonical home (next section). Full procedure:
**`vh-agent-harness docs preserved-managed-reconciliation`**.

## Making the customization permanent (routes)

- **Additive customization** → an **overlay pack**: new paths only. A pack
  cannot replace a builtin at the same path — the render fails closed with
  `ErrShadowBuiltin`.
- **Same-path replacement** → raise the file to **`project_owned`** in
  `.vh-agent-harness/harness-ownership.yml` with a direct edit, then
  re-check and re-apply the platform delta each release (runbook options
  B1/B2 in `preserved-managed-reconciliation`).

## Verification scope rider

This notice verifies **link integrity only** — the grammar-conformance and
edge-closure receipts above are link-level facts.
The behavior of preserved files is not verified: nothing here claims or
checks that a preserved `state-lib.js` behaves like the platform's current one.
