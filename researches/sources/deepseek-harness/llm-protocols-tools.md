## 1. Tool-execution pipeline, end-to-end

Canonical narrative doc: `dsh:docs/tool-execution-pipeline.md` (read in full). Authoring contract for individual tools: `dsh:docs/cookbook/adding-a-tool.md`.

### 1.1 The pipeline (per tool call)

1. **Pre-execution logging** — `tool/call` event is logged *before* anything executes (the intent is durable even if execution never happens).
2. **`tools/pre-execute` waterfall** — hooks / permission / sandbox observers run before dispatch.
3. **Monotonic guards** — `ctx.tools.guard()` and identity-protected invariants that may only tighten, never loosen, mid-flight.
4. **`ctx.approval` one-shot** — approval is a single-shot interaction; absent or unanswerable approval = **deny** (fail-closed).
5. **`tools/execute` around-dispatch** — timeout / retry / metrics wrap the actual execute body.
6. **Execute body** — the tool's own code.
7. **`fs/write-intent` + `fs/edit-intent` gates** — filesystem mutation passes intent gates inside the pipeline.
8. **Tool-owned events** — the tool emits its own typed events on the stream.
9. **`tools/post-execute` observers** — may accept / block / replace / addContext on the result.
10. **Registry normalization** — thrown errors become `isError` results rather than pipeline exceptions.
11. **`finalizeContent`** — projects the raw result into canonical content.
12. **Frozen `tools/result`** — the terminal result event is frozen (immutable after emission).
13. **`additionalContexts` FIFO** — context added by post-execute observers is queued FIFO.

**Code Mode sub-calls re-enter the full pipeline** with the parent's token and a `tool/code-dispatch` event — nested execution is the same pipeline, not a shortcut.

### 1.2 The execute contract (tool author's view)

From `dsh:docs/cookbook/adding-a-tool.md`:

- `defineTool` validates args against a `ParameterSchemaSpec` **before** `execute` runs.
- Tool identity fields are **protected**: args are detached, lossless-JSON-serialized, and frozen; the exec token is opaque; `callId`/`name`/`agent`/`signal`/`parent` are immutable for the call's lifetime.
- Output is **one canonical JSON value** validated against `output.schema`.
- `throw` or invalid output ⇒ normalized `isError` result (never a raw pipeline crash).
- `presentationMeta` projects replayable card data (presentation separated from the canonical value).
- **Presenters are PURE** — they run on the live stream *and* on log replay, so they may do no I/O.
- Background work goes through `ctx.jobs.start` and returns the canonical value `{kind:'background', jobId}` — a canonical result still exists; it points at a job.

### 1.3 Tool-catalog gate (generated + gated catalog)

From `dsh:docs/tool-catalog.md` (all 1873 lines read), `dsh:scripts/gen-tool-catalog.ts`, `dsh:package.json` (line 113: `verify-tool-catalog`), `dsh:scripts/run-gates.ts` (~line 588):

- The catalog is **generated by booting each tool plugin on a fresh real Cordis Context** — `SystemPrompt` + `ToolRuntime` + stub services are mounted (a `CatalogAttachmentStore`, and a catalog subagent provider advertising capabilities) — then reading `ctx.tools.schemas()`.
- Rationale: tool schemas are **not statically knowable** (runtime enums, config-driven tool names, raw MCP JSON Schema passthrough). Harvesting at boot is the only honest source.
- **Completeness guards**: `assertManifestComplete` globs `packages/*/tool-*` against the boot manifest (a new tool package that was never booted fails the gate); `assertToolsHarvested` fails any package that registers zero tools.
- `pnpm run verify-tool-catalog` runs the same script with `--check` and **byte-compares** the generated catalog; it is wired into `run-gates.ts` and the doc-sync flow, so a merged change with a stale catalog fails CI.

## 2. API gateway + LLM stack, end-to-end

### 2.1 API gateway (`dsh:docs/api-gateway.md`, read in full)

- Cross-package calls are declared with `@Remote` / `@RemoteScope` decorators; **strict Host/Client contracts are generated via `ts.Program` analysis** during the Host tsdown build.
- Wire shape: `POST /api/<ns>/<method>` over a shared Connection RPC.
- Per-call **descriptor + codec validation** on both ends; lookup-style providers get a `lookup-unavailable` outcome rather than a crash.
- **SRC fallback**: source boots (dev mode without a built Host) fall back to direct in-process calls.
- **Unclaimed endpoints** fall back to an API Proxy — the gateway degrades instead of dead-ending.

### 2.2 LlmRuntime (`dsh:packages/llm/llm/src/index.ts`, 947 lines, read in full)

- Adapter **registry with atomic `replace()`** route swap — a route never momentarily points at two adapters.
- **`prepareCall()` is one-shot and registration-bound**: a prepared call dispatches only against the adapter registration it was created under; a stale registration yields `INVALID_PREPARED_CALL` rather than dispatching to the wrong adapter.
- **`replayState` is stripped** unless the *same adapter instance* owns both the historical route and the target route — replay across an adapter swap is refused, not guessed.
- **Failure normalization split**: all *adapter* failures are normalized to a terminal finish `{kind:'error'|'aborted'}`; *middleware/consumer* failures stay thrown. The stream always terminates exactly once, in-band.
- `llm/adapters-updated` is a **contained-observer event** (observers can't corrupt the dispatch table).
- `llm/stream` waterfall composes the middleware chain around the adapter stream.

**StreamChunk protocol** (`dsh:packages/llm/llm/src/types.ts`): `block-start` / `text-delta` / `reasoning-delta` / `tool-call-delta` (args as raw string) / `block-end` / `usage` / `finish` — **usage arrives BEFORE finish; nothing arrives after finish.**

### 2.3 Retry — at durable turn boundaries, not inside the stream

From `dsh:packages/llm/llm-retry/README.md` + `dsh:packages/llm/llm/src/retry-policy.ts`:

- Retry is **NOT inside `llm/stream`**. It executes at the agent-loop level via the `agent/request-error` waterfall.
- Each retry is a **fresh numbered turn** with durable `llm/retry` + `llm/retry-started` events — retries are first-class history, visible in replay.
- Normal mode: 2 retries, on codes `[EMPTY_RESPONSE, RATE_LIMIT, SERVER, TIMEOUT, TRANSPORT]`, backoff 500ms→10s, 10% jitter; an `always` mode also exists.
- `providerRetryAfterMs` honored when ≤ cap.
- Retry policy is **captured immutable at registration** (later config changes don't mutate in-flight policies).

### 2.4 Twin adapters

**llm-deepseek** (`dsh:packages/llm/llm-deepseek/` — README + types at pass 1; `src/{adapter,sse,translate,serialize}.ts` spot-read in pass-2 top-up; fold in §3.1):

- Direct `fetch` + `eventsource-parser` SSE parsing (no heavy SDK).
- Route `deepseek-official`; **dynamic per-operation option resolution via thunk** (options resolved at call time, not registration time).
- **Credentials resolved per call** (never cached on the adapter).
- Thinking-dialect serialization; sends `x-deepseek-harness-user-id` / `session-id` / `compact` headers.

**llm-pi-ai** (`dsh:packages/llm/llm-pi-ai/` — README-level; src `adapter/catalog/config/context/discovery/provider/replay/stream` unread):

- Multi-provider dictionary profiles; **dormant mounting** (adapters mount without activating until a profile targets them).
- `modelOverrides`; per-model `reasoningEfforts` wire-spelling maps (UI names ↔ wire spellings).
- Immutable per-operation snapshot of resolved options.
- **SDK `maxRetries` forced to 0** — retry belongs to the agent loop (§2.3), never the transport SDK.

### 2.5 Token meter (`dsh:packages/llm/token-meter/` — README-level; src incl. `estimate.ts`, `projection.ts`, `usage-projection.ts` unread)

- Replay-aware **4-chars/token heuristic** anchored by provider-reported usage when present.
- `projectedTokens` = next-request estimate.

### 2.6 MCP client (`dsh:packages/mcp/mcp-client/` — README + `src/index.ts` + `src/tools.ts` read in full; `connection.ts`/`transport.ts` spot-read in top-up)

- **One client instance per server.**
- Tool naming: `mcp__<serverName>__<rawName>` with 64-char normalization + 12-hex SHA-256 collision hash suffix on truncation; the **raw name only ever appears on the wire**.
- **Two-phase generation swap**: on reconnect, the new tool generation is staged, then swapped atomically. A fetch failure keeps the old generation; a registration conflict **rolls back the whole generation** — never a partial tool set.
- `isError` MCP results become thrown errors (visible failure, not silent data).
- `structuredContent` schema-subset fallback when the full schema isn't usable.
- **Budgeted reconnect**: 500ms→30s doubling backoff, 10 attempts per outage, uptime resets the budget.
- `listToolsUncached` / `callToolUncached` bypass the MCP SDK validator caches for freshness-critical paths.

**Pass-2 src verification** — `connection.ts` (351 ln, read in full): frozen `RECONNECT_DEFAULTS {enabled:true, initialDelayMs:500, maxDelayMs:30000, maxAttempts:10}`; the **stability window is `maxDelayMs`** (uptime ≥ maxDelayMs resets the attempt budget, so a crash-looping server whose connects briefly succeed still exhausts the cap); **exhaustion unregisters the server's tools and stops** — only disposal/HMR recovers; `GENERATION_CLOSE_TIMEOUT_MS=5000` — if a failed generation does not close in time, reconnection **stops rather than overlap server processes** (fail-closed against duplicate children); a `syncChain` promise chain **serializes every tool sync across all generations** (no interleaved dispose-previous/register-next → no double-dispose or leaked generation); the `isCurrent(generation)` guard makes racing close/error signals idempotent (one disconnect decision per generation); `ToolListChanged` handler is registered **before** connect so a list change during initial sync queues behind it; a re-sync fetch failure **keeps the previous generation's registrations** (keep serving the last good list); `failOnStartupError` flips initial registration-failure mode from `contain` to `throw`; reconnect timers are `unref()`'d (never hold the process open); `dispose()` = clear timer → close current → await in-flight attempt + sync chain → unregister all.
`transport.ts` (50 ln): stdio (child env = `scrubbedParentEnv()` — credential-shaped and stale `DSH_*` names dropped — plus explicit env) or Streamable HTTP (URL + headers); the scrub *definition* is shared with the subprocess seam though the MCP SDK owns the spawn.

### 2.7 ACP (`dsh:packages/acp/` — README + `src/` lines 1–150 of 436)

- **Automation-only** protocol surface: no interactive approval assumed.
- **Committed-text-only streaming**: `agent_message_chunk` is emitted per *committed* block (no speculative deltas) — replay honesty over latency.
- Multi-session support with branded session ids + **exact-agent-identity impostor checks** (a session claiming the wrong agent identity is rejected).
- **One-shot permission bridge, fail-closed**: unanswerable permission request = deny.
- Teardown **drains continuable descendants** before exit.

### 2.8 SDK / feedback / identity (README-level; src unread)

- **SDK** (`dsh:packages/sdk/{client,protocol,server}/`): NDJSON JSON-RPC on stdio. `session.event` = unfiltered event stream; `session.status` = state queries; `prompt` returns an **enqueue receipt only** (not a completion). **stdout-is-protocol purity**: anything the server prints to stdout is protocol, so libraries must not leak prints. Client close ladder: shutdown → EOF → SIGTERM → SIGKILL.
- **command-feedback**: log-only `feedback/record` events, **zero model surface** (feedback never enters the conversation), telemetry-sharing disclosure built in.
- **message-feedback**: storage sidecar; **compare-and-set versions** for concurrent feedback edits; Typert `@Remote` endpoints for transport.
- **identity/anonymous-user-id**: anonymous UUID identity correlated across OTel, feedback, and the provider header (`x-deepseek-harness-user-id`).

### 3.4 packages/lsp

- Group README (pass 1) + all three sub-package READMEs (pass 2 top-up) read; src unread.
- `lsp` — the **LSP capability seam**: abstract `LspService` (`ctx.lsp`) exposing exactly **four semantic operations** (`goToDefinition`, `findReferences`, `goToImplementation`, `hover`) and **no generic JSON-RPC escape hatch**, so no protocol payload or unreviewed command/mutation can reach a provider. Provider registry keyed by branded id + **exclusive extension ownership** (overlaps fail registration; registration/HMR order never changes routing). `LspQueryResult` is a **closed discriminated union** (consumers `switch` to exhaustiveness); `LspError` taxonomy (`LSP_INVALID_PROVIDER`, `LSP_CONFLICT`, `LSP_UNAVAILABLE`, `LSP_DISPOSED`, `LSP_MALFORMED_RESPONSE`). Providers register capabilities, not tools; the model-facing surface belongs entirely to `tool-lsp`.
- `lsp-stdio` — generic stdio backend, one isolated provider per configured server entry; **transient-open per query** (`didOpen` full text v1 → query → `didClose` in `finally`; no didChange/cache/LRU needed); per-workspace abortable serialization queues (distinct workspaces parallel); single-flight one process per `(server id, workspace)`; transport failure during a read-only query → await disposal + **one retry on a fresh process**; subprocess tree-kill (POSIX process-group / Windows `taskkill /T /F`) with quiescence confirmed by tree-liveness wait, not kill outcome; env forwarding **scrubs credential-shaped names** (`KEY`/`PASSWORD`/`SECRET`/`TOKEN`); emits no `fs/observed` (an LSP read does not satisfy read-before-write policy); `initialize.processId` is null (server must not monitor the harness).
- `tool-lsp` — model-facing `lsp` tool: one-based UTF-16 cursor ↔ zero-based conversion; workspace root required from session `header.cwd` with no fallback (`LSP_WORKSPACE_REQUIRED`); limits `maxLocations=100`, `maxResultChars=16000`, `timeoutMs=60000`; `findReferences` always includes declarations; verbatim system-prompt guidance pinned at order 112; canonical result is the raw Service Definition union (Code Mode can inspect zero-based ranges directly).

### 3.5 packages/credentials

- `credentials` — README read: **references-not-secrets doctrine** (stores *references* to secrets, never secret values), **resolve-per-operation** (resolved values never cached; empty result = absent), 4-layer precedence: frozen env snapshot > `0600` `.credentials.yaml` under `0700` dir (cross-process lock, comment-preserving patches, POSIX perm-bit rejection) > project `.env` > user `.env`. **Honest security boundary stated in the README itself**: 0600 stops *other users*, NOT the model; never exposes the file path; never injects into process env.
- `credentials-local` — README read in full at pass 2 (file-backed provider for the seam): four layers with source ids (`env` always wins and is *visibly read-only* — `describe()` reports `writable:false`, `set`/`unset` reject rather than write a change the reader would never see; `file` = managed store wins over both `.env` layers; `project-env` over `user-env`). Empty string in the document is rejected outright (`unset` removes, it does not blank — empty = absent per seam rule). Src unread for both.

## Transferable ideas → vh-agent-harness

1. **Generated + gated capability catalog** (F-CAT-1/2). vh-agent-harness analog: any place we enumerate agent/tool/skill surfaces for docs or drift checks (`doctor`, `README.agent.md` accuracy, rendered-corpus manifests). The dsh lesson: when truth is only knowable at runtime, *harvest it by real boot* and gate on byte-compare, plus completeness guards that fail silently-added packages. (Adaptation note: our corpus is static Go templates, so our catalog can stay static — the transferable part is the *gate*, not the boot.)
2. **Pipeline waterfall/guard split** (F-PIPE-1..5): observers that can accept/block/replace/addContext around a frozen canonical result, throws normalized to `isError`, presenters pure for replay. Maps onto our behavioral-closure/closeout event thinking and any future tool-execution pipeline for OpenCode tools: make the terminal artifact immutable and make every mutation-adjacent concern an *around* stage, never inline in the body.
3. **prepareCall registration-binding + atomic route replace** (F-LLM-1/2): a provider-routing swap in vh-agent-harness (model/provider routing, MCP server regeneration) should be atomic with stale-preparation refusal (`INVALID_PREPARED_CALL` analog) rather than best-effort re-dispatch. Pairs with MCP's two-phase generation swap (F-MCP-2): stage the new generation, swap atomically, roll back whole on conflict.
4. **Retry at durable turn boundaries** (F-RETRY-1/2 + F-ADP-2): retries as fresh numbered turns with durable events, transport SDK retry disabled — visible, replayable, budgeted. For us: any harness-level retry (provider calls, MCP reconnects) should emit durable events and honor provider retry-after within a cap, instead of hiding inside a transport library.
5. **Credentials references-not-secrets + honest boundary** (F-CRED-1): store references, resolve per operation, never cache, never print paths, and *state the threat model honestly in the docs* (permissions stop other users, not the model). Directly applicable to our provider/API-key handling and diagnostics-export redaction.

Secondary (noted, not elaborated): fail-closed one-shot approval (F-PIPE-2, F-ACP-1); stdout-is-protocol purity (F-SDK-1); committed-text-only streaming for automation surfaces (F-ACP-1); anonymous identity correlation across telemetry surfaces (F-ID-1).
