## 0. The natural-miss trick (why misses are measurable from logs)

A miss normally leaves no trace. But every **solo/partial-upheld catch** is a natural miss
**with a known answer**: a coordinator-UPHELD finding (disposition `block`/`defer`) in a
**co-present** round (≥1 GPT-class AND ≥1 non-GPT leaf, all non-empty v2) that was matched by
only a SUBSET of the co-present leaves. Each co-present non-empty leaf that did NOT match it
**missed a known-real defect** — same diff, same static uniform prompt, different leaf model.

This is a controlled natural experiment. Its ground truth is **stronger than S3's**: a finding
is counted as a miss only when it is (a) coord-upheld **and** (b) independently corroborated by
≥1 co-present leaf (a different model on the same input). The independent corroboration is the
control that isolates per-model behavior. The residual circularity — the upholding coordinator
is itself a model (mostly `glm-5.2-high`), so "upheld" measures agreement, not truth — is
carried as an explicit open question (§7 Q1), as the task framed it. The trick **sidesteps the
DROPPING circularity** S3 was built around (S3 asked "was the drop correct?"; M1 asks "was the
uphold real and a co-present leaf missed it?").

**Scope fences (load-bearing):**
- In-scope directories: `vh-agent-harness`, `vh-solara` ONLY. The co-mingled sensitive
  third-party directory is EXCLUDED from every query and never read.
- GPT-class = {`gpt-latest:free`, `gpt-5.5:free`} (same as S6/q30).
- Quarantine = {`kiro-claude-opus-4-5`} (PAID, no `:free`; 21-run / 1-day / 100%-empty
  transient) — excluded from all denominators; never defines anything.
- Keying = exact `json_extract(model,'$.id')`; `:free`/paid + version DISTINCT.
- Matching = score ≥ 0.45 (category 0.25 + location 0.45/0.55 + token-overlap up to 0.35),
  reused **byte-identically** from q30 (confirmed against `q30_output.json.matching`).

caught it). It is excluded from the natural-miss population because it is not a *differential*
outcome — there is no co-present leaf that DID catch it to anchor the controlled comparison.

cases the logs cannot separate without leaf-text reading: (a) coordinator-unique findings
(the coordinator detected something no leaf did) vs (b) leaf findings phrased too differently

## 3. Leg 2 — Qualitative mechanism classification (methodology FINAL; per-miss fill PENDING on §5)

### 3.1 What Leg 2 needs

For each of the 71 sampled misses (§3.2), classify into **exactly one** mechanism:

| mechanism | rule |
|---|---|
| **a. PROMPT-GAP** | the class/concern is not something the static prompt asks for (no model would raise it under the current prompt) |
| **b. CONTEXT-ABSENT** | the evidence needed was NOT in the diff/context handed to the leaf (e.g. the contract/defense lives in a file not included) |
| **c. SKIM/COVERAGE** | the evidence WAS in the leaf's input but the leaf never examined that region (raised nothing there, or only touched other files) |
| **d. RAISED-WEAK / MIS-EXPRESSED** | the leaf DID notice but expressed it as "verified fine" / a non-finding / a too-low severity that did not match |
| **e. GENUINE-CAPABILITY** | input had it, leaf examined that region, reasoned, and still did not identify the defect — **the ONLY model-dependent bucket** |

## 4. The a–d MODEL-INDEPENDENT fix proposals (design; empirical validation awaits Leg 2)

These are **harness-level proposals**, not validated fixes. Each is keyed to its mechanism
definition and mapped to an existing property/finding. Their *relative leverage* (which
mechanism dominates) is exactly what Leg 2 measures; the proposals stand regardless, because
they are model-independent by construction.

### a. PROMPT-GAP → prompt asks / lens extension
- **Mechanism:** the class/concern is not something the static uniform prompt asks any leaf to
  look for, so no model raises it under the current prompt.
- **Proposal:** extend the **shared** leaf prompt's issue-category coverage lens (the same
  static prompt all 4 leaves receive — an untested, model-independent lever per the task). Add
  an explicit "raise findings in these classes" enumeration tied to the canonical category set.
- **Model-independence:** high — a prompt gap suppresses signal for every model uniformly; a
  prompt extension lifts every model uniformly.

### b. CONTEXT-ABSENT → harness context expansion
- **Mechanism:** the evidence needed to identify the defect was NOT in the diff/context handed
  to the leaf (the contract, invariant, or defense lives in a file/region not included in the
  review input).
- **Proposal:** expand the review context the harness assembles per changed symbol — include
  the **declaring file region** (signature + immediate contract/doc) for each changed symbol,
  not just the diff hunk. Name what to include: the symbol's declaration, its doc comment, and
  the immediate caller/callee signatures reachable from the hunk.
- **Model-independence:** high — context absence is a harness-input defect, identical across
  models; expanding the input lifts every model.

### c. SKIM/COVERAGE → coverage-forcing checklist (maps to the coverage-enforcement property)
- **Mechanism:** the evidence WAS in the leaf's input but the leaf never examined that region
  (raised nothing there, or only touched other files).
- **Proposal:** add a **per-changed-file / per-changed-symbol coverage checklist** to the
  shared leaf prompt, AND a gate-shaped **coverage-completeness validator** at the
  commit-review boundary that compares each leaf's examined-region set against the diff's
  changed-region set and refuses "complete approval" when coverage is partial.
- **Mapping (load-bearing):** this is **exactly** the **coverage-enforcement** property
  (`researches/decisions/2026-07-28-success-report-integrity-and-working-tree-stewardship.md`,
  Finding A): "an agent must account for everything in its declared scope before reporting
  success… a partial leaf result is insufficient." Finding A's failure-mechanism is literally
  "partial examination represented as complete approval" — the definition of mechanism (c). Its
  specified remedy is "a deterministic validator [that] compares [declared scope and coverage
  evidence]; a gate-shaped completeness validator may BLOCK." Mechanism (c) is the miss-side
  instance of the coverage-enforcement failure the property already names; the fix is the
  property's already-specified validator, applied to the leaf prompt + the review boundary.
- **Model-independence:** high — coverage enforcement is a structural gate, not a model
  capability.

### d. RAISED-WEAK / MIS-EXPRESSED → prompt-hygiene (maps to S3 §5.4)
- **Mechanism:** the leaf DID notice but expressed it as a "verified fine" note, a non-finding,
  or a too-low severity that failed to match the upheld finding.
- **Proposal:** add a **prompt-hygiene rule** to the shared leaf prompt: suppress positive
  "I verified X is fine / clean / sanctioned" emissions in favor of either a concrete finding
  or silence; require any noticed concern to be raised as a structured finding at a defensible
  severity, not buried in a verification note.
- **Mapping (load-bearing):** S3 §5.4 found **~26% of dropped "findings" are positive
  verification notes** (the leaf *confirming* something is correct, not raising a concern) —
  audit-trail artifacts mislabeled as findings. Mechanism (d) is the symmetric failure on the
  miss side: a real concern expressed as a positive note (or under-severitied) that fails to
  register as a finding. S3 §5.4 already recommended "the prompt could suppress 'I verified X
  is fine' emissions without losing detection value"; (d) generalizes that to "any noticed
  concern must be raised as a finding, not as a verification note."
- **Model-independence:** high — expression hygiene is prompt-shaped.

### Why (e) has no model-independent fix
(e) GENUINE-CAPABILITY is the residual after a–d: the input had the evidence, the leaf examined
it, reasoned, and still missed it. No prompt/context/coverage/expression lever can close it —
it is the model's reasoning ceiling on that input. **(e) is therefore the only bucket that
requires a model-capability lever** (better model, or ensemble/diversity to make the same
defect independently re-detectable). The size of (e) is the headline precisely because it
separates "harness can fix this" (a–d) from "model must improve" (e).
