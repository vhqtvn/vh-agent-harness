## 1. Summary

SparseRead is a training-free, model-agnostic "reading control layer" situated between a tool-using AI agent and external artifacts (webpages, PDFs, code repositories, spreadsheets, and bulky tool responses).

- **Motivation [Fact]:** Agents habitually over-read. External observations account for 60–80% of trajectory tokens across common benchmarks. Unmodified agents consume up to 17.3× more tokens without quality gains. Crucially, excess content actively dilutes evidence, inducing erroneous tool use, source confusion, and failure to stop.
- **Core thesis [Fact]:** SparseRead governs content admission itself rather than retrieving or compressing content after admission.
- **Mechanism [Fact]:** The agent declares a structured Read Intent. The layer returns a bounded, source-anchored `EvidencePack` with explicit slot-level coverage. A Budgeted Read Gate bounds cumulative raw exposure per reading episode with a faithful full-view fallback that guarantees at most $2L$ worst-case exposure (Proposition 4.1) *(amended — see Code audit addendum)*.

## 2. Architecture

The system operates across two planes:
1. **Control plane:** Intent interpretation, Reader selection, evidence recording, and admission governance.
2. **Evidence plane:** Artifact-specific Reader backends.

**Key conceptual split (§2.1) [Fact]:** Processing scope vs. model exposure vs. evidence coverage — these three dimensions need not scale together. Full processing does not imply full exposure. Ordinary sparse reads preserve preceding dialogue turns for prefix-cache reuse; full-view fallback retires earlier sparse observations (sacrificing prefix reuse to prevent context bloat) *(amended — see Code audit addendum)*.

### a. Read Intent Protocol (§4.1)
The protocol coordinates a stateful sequence of evidence requests.
- **Intents [Fact]:** Each access specifies a structured access intent, which takes precedence over any broader session intent derived from the user's opening request *(amended — see Code audit addendum)*. Underspecified intents receive a bounded `Object Preview` (also explicitly requestable via `scout`).
- **EvidencePack contract [Fact]:** Consists of source-anchored evidence + scope examined + amount exposed + per-slot coverage *(amended — see Code audit addendum)*. Coverage indicates which portions were examined; coverage does *not* declare evidence sufficiency.
- **Versioning & episodes [Fact]:** A SHA-256 artifact fingerprint versions external artifacts *(amended — see Code audit addendum)*. Any version change immediately invalidates previously recorded evidence and coverage. A reading episode spans all accesses to a single artifact version under one objective *(amended — see Code audit addendum)*; `refine` and `verify` actions share the existing evidence record and budget.
- **Stable action set [Fact]:** Five fixed actions $A = \{\text{scout}, \text{focus}, \text{collect}, \text{refine}, \text{verify}\}$. Each Reader maps these actions to artifact-specific operations; adding new Readers never expands the action set.
- **Algorithm 1 structure [Fact]:**
  1. `SyncArtifactVersion` by fingerprint.
  2. `Validate(ResolveIntent(access > session))`.
  3. `EnsureEpisode` ($f = \text{fixed full view}$, $L = |f(o)|$).
  4. If `NeedsFullModelView` or `NativeFit` $\to$ `FullViewFallback`.
  5. If `Underspecified` or `scout` $\to$ return `ObjectPreview`.
  6. `SelectReader` (balancing reliability and cost); if none $\to$ `FullViewFallback`.
  7. Prepare batch $b$; if `EstimatedSize(b)` $> L - E \to$ `FullViewFallback`.
  8. `SerializeIntact(limit = L - E)`; if overflow $\to$ `FullViewFallback`.
  9. Record evidence + update cumulative exposure $E \to$ return `EvidencePack`.
  - **FullViewFallback semantics:** Retire earlier sparse observations from dialogue history, deliver $f$ once (reusing if already exposed), and close the episode *(amended — see Code audit addendum)*.

### b. Adaptive Reader Backends (§4.2, §5)
- **Implemented Readers [Fact]:** Text/PDF (page/heading anchors, bounded local passages), tables/JSON (schema, samples, row/column projections; can execute exact operations over full tables exposing only the result + row count + provenance, or calculation-ready TSV fragments), multi-file collections (inventory followed by candidate file selection), script libraries (AI-for-Science) *(amended — see Code audit addendum)*.
- **Internal reader configuration [Fact]:** $r = (\text{Reader}, \text{location method}, \text{exposure form})$.
  - Location/processing methods: lexical, BM25 windows, hybrid dense retrieval; column queries; key-path lookup.
  - Exposure forms: anchored snippets, lossless compact view, exact-operation result + provenance.
- **Configuration selection [Fact]:** *(amended — see Code audit addendum)* Evaluated per request group $g$ (artifact type $\times$ size band $\times$ intent type):
  $$r^* = \arg\min \hat{C}(r \mid g) \quad \text{s.t.} \quad \hat{p}_{\text{valid}}(r \mid g) \ge \tau$$
  where $\hat{C}$ estimates character exposure + execution + likely follow-up reads; $\hat{p}_{\text{valid}}$ is calibrated on dev requests using the lower bound of a 95% Wilson score interval; $\tau = 0.6$ fixed prior to evaluation. Request groups with $<20$ calibration requests remain non-adaptive (using default configuration, falling back to full view if below threshold). If no configuration qualifies, fallback to full view occurs — never silent threshold relaxation.

### c. Budgeted Read Gate (§4.3, Proposition 4.1, Appendix A)
- **Accounting unit [Fact]:** Budget is strictly measured in **CHARACTERS**.
  - $f(o)$ = least expensive faithful full view (native read or lossless compact representation).
  - $L = |f(o)|$ characters.
  - Cumulative sparse payload exposure within an episode is bounded by $E \le L$. Both $f$ and $L$ are immutable within an episode.
- **Gate rules [Fact]:** Deliver full view when the model requires whole-artifact inspection or when no suitable Reader exists. Small artifacts bypass sparse reading via `NativeFit`. Otherwise, sparse reading applies with both a pre-delivery estimated-size check and a post-serialization check of the actual payload. If the next batch cannot fit intact within the remaining budget ($L - E$), it is withheld and $f(o)$ is delivered *(amended — see Code audit addendum)*. Evidence is never truncated in ways that break semantic meaning or detach source anchors.
- **Fallback triggers [Fact]:** (1) `needs-full-model-view` intents; (2) no eligible Reader/configuration; (3) batch exceeds remaining budget; (4) serialization overflow.
- **Theoretical guarantee (Proposition 4.1) [Fact]:** Total unweighted artifact exposure per episode $\le 2L$ (tight constant bound) *(amended — see Code audit addendum)*.
- **Explicit boundary [Fact]:** Proposition 4.1 does *not* bound replay-weighted context, billed tokens, latency, or oracle performance. Full processing $\neq$ full exposure.

### d. Unified Reader Interface & Integration
- **Contract [Fact]:** Identical `EvidencePack` schema across all configurations; fixed 5-action set; Reader registration by `(artifact types, actions, cost profile)` — adding a Reader makes it immediately available to every harness without adapter modifications.
- **Architectural boundary [Fact]:** Sits strictly **OUTSIDE** the agent model — no weights are modified, and no generative model is used for compression. Model-facing guidance (`SKILL.md`) is purely advisory; intent validation and exposure budget enforcement reside in the runtime core ("no harness depends on the model's compliance for its guarantees").
- **Agent-facing tools [Fact]:**
  - `sro_preview(path)` $\to$ bounded preview + `FileCard`.
  - `sro_read(target, mode, hint)` $\to$ `EvidencePack`.
  - `sro_raw(raw_ref)` $\to$ explicit raw fallback.
- **Related compression backends [Fact]:** SWE-Pruner and Squeez are cited as potential alternative compression backends within this interface.

## 3. Evaluation (§6)

- **Setup [Fact]:** Main evaluation matrix executed on NanoBot v0.2.0 across six models:
  - Medium: Qwen3.6-Plus, DeepSeek-V4-Flash.
  - Large open: DeepSeek-V4-Pro, GLM-5.1, Kimi-K2.5.
  - Closed frontier: Claude Opus 5.
- **Scenarios [Fact]:** Five domains across ~125 tasks total (task count reported in repo README):
  1. Long-context reading (LooGLE + PinchBench + Workspace-Bench-Lite).
  2. Multi-file audit/diagnosis (QwenClawBench).
  3. Structured analysis (QwenClawBench + SpreadsheetBench Verified).
  4. Web deep search (FRAMES + BrowseComp-Plus, fixed corpus).
  5. AI for Science (MDGYM LAMMPS script generation).
- **Baselines [Fact]:** Naive (unmodified full-text reading), RAG Static (BGE-M3 + BGE-Reranker-v2-M3, top-8 chunks / 4,096 tokens, retrieved once), RAG Agent (iterative retrieval), ACON, Observation Masking (Complexity Trap baseline, retaining latest 10 observations).
- **Headline results [Fact]:**
  - Token consumption: reduced by **−15.7% to −92.9%** (median reduction **61.4%**).
  - Wall-clock time: reduced by **−23.0% to −89.0%** (median reduction **53.7%**).
  - Task success score: preserved or improved in **29/30 settings (≈97%)** — the sole regression occurred with GLM-5.1 on AI for Science.
- **Per-scenario breakdown [Fact]:**
  - Long-context reading: −76.5% to −92.9% tokens; −67.1% to −89.0% wall time.
  - Multi-file audit/diagnosis: −26.8% to −74.5% tokens (wall time is figure-only in the paper).
  - Structured analysis: −15.7% to −64.1% tokens (wall time is figure-only in the paper).
  - Web deep search: −31.0% to −43.0% tokens; −23.0% to −37.0% wall time; all six models gained +5 to +14 percentage points in accuracy.
  - AI for Science: −82.7% to −89.1% tokens; −28.3% to −63.0% wall time (across 5/6 models; GLM-5.1 regressed).
  - Claude Opus 5 across all 5 scenarios: −41.0% to −89.0% tokens; −35.0% to −78.1% wall time.
- **Comparison against baselines (15 settings) [Fact]:**
  - SparseRead preserved or improved score across all 15 settings, saving 27.0–92.9% tokens and 23.0–88.9% wall time.
  - Achieved the absolute lowest token count in 6/15 settings and lowest wall time in 9/15 settings.
  - Set both token and time minimums for all five models evaluated on multi-file audit (+17.8 to +34.5 pp score gain).
  - RAG Static was faster on web search but produced below-Naive accuracy in 9/15 settings.
  - RAG Agent degraded score in 8/15 settings and exceeded Naive wall time in 8/15 settings.
  - ACON degraded score in 5/15 settings and increased both token and time costs in 6/15 settings.
  - Observation masking degraded score in 5/15 settings.
- **Cross-framework portability (Table 1) [Fact]:**
  - Evaluated on 18 cells (3 frameworks $\times$ 6 models): 18/18 cells reduced both tokens and wall time.
  - 15/18 cells preserved or improved accuracy score (three cells decreased slightly by 0.013–0.031).
  - Paper reported median savings:
    - NanoBot: 65.0% tokens / 59.3% time.
    - OpenCode: 65.2% tokens / 63.9% time.
    - OpenClaw: 30.6% tokens / 28.8% time.
  - Extremes:
    - NanoBot + Kimi-K2.5: −92.9% tokens / −85.4% time (+0.598 score).
    - OpenCode + Kimi-K2.5: −83.7% tokens / −73.7% time (−0.031 score).

## 4. Ablations (§6.5)

- **Read Intent Protocol [Fact]:**
  - Combining access and session intents reduced repeated reads from 4.8 to 1.5 per task (−68.8%).
  - Untraceable evidence dropped from 28% to 8%.
  - Verification actions resolving an actual information gap increased from 37% to 89%.
  - Final answers failing due to missing evidence fell from 25% to 5%.
  - Access intent alone outperformed session intent alone across every diagnostic metric.
- **Reader backends (Text location methods on 47 LooGLE documents / 741 questions; hit = $\ge 80\%$ annotated evidence coverage) [Fact]:**
  - Lexical matching: 39.5% hit rate @ 780 median characters.
  - BM25 windows: 60.1% hit rate @ 1,497 median characters.
  - Hybrid dense retrieval: 65.3% hit rate @ 1,490 median characters (+5.2 pp over BM25 at essentially identical exposure).
  - BM25 + expanded windows: 56.7% hit rate @ 2,106 median characters.
  - *Paper acknowledgment [Fact]:* This ablation demonstrates backend retriever performance but does not isolate the marginal contribution of the dynamic configuration selector over fixed configurations.
- **Budgeted Read Gate (5 tasks $\times$ 3 repeats, DeepSeek-V4-Flash; character exposure ratio $(E + L) / L$) [Fact]:**
  - Post-delivery checking permits budget overshoot (upgraded runs reached 2.10–2.33$\times$).
  - Pre-delivery estimation enforces the bound, keeping all runs within 1.62–1.93$\times$.

## 7. Acknowledged Limitations

- **Exposure bound scope [Fact]:** The $2L$ upper bound applies strictly per episode to unweighted **CHARACTERS**. It does not constrain replay-weighted context accumulation, billed provider tokens, latency, or oracle task performance.
- **Cache invalidation on fallback [Fact]:** When a reading episode triggers `FullViewFallback`, retiring previous sparse observations invalidates prefix-cache reuse from that edit point forward; tokens already billed for sparse attempts cannot be recovered.
- **Coverage vs. correctness [Fact]:** Coverage indicates what text slots were inspected, not whether the extracted evidence is semantically sufficient or factually correct.
- **Pathological degradation [Fact]:** Forcing sparse reading on global-statistics or rule-coding tasks that inherently require whole-artifact inspection *increased* token consumption by 309% and 210% (the rationale for the Gate's NativeFit and full-view triggers).
- **Ablation limitations [Fact]:** The Reader ablation does not isolate the dynamic configuration selector's benefit over static assignments. The gate economics ablation (App C) analyzed an earlier prototype policy, whereas Figure 8(c) validates the current character-based enforcement.
- **Unexplained data points [Fact]:**
  - The GLM-5.1 performance regression on AI for Science has no identified cause in the paper text.
  - Three cross-framework cells exhibited small score decreases (0.013–0.031) without detailed analysis.
  - Benchmark accounting counts do not reconcile cleanly across sections: §6.2 cites 29/30, Appendix C cites 26/30, and a scenario tally excluding web search cites 22/24 (22/24 + 6/6 web would imply 28/30, leaving one setting unaccounted for).

## 8. Expert Critique

1. **Asymmetric fallback risk [Inference]:** The fallback semantics risk masking degradation. Retiring earlier sparse observations is an irreversible history modification. If early sparse reads misled the model into irreversible intermediate actions, providing the full view later cannot undo those steps. Furthermore, reported token savings partially stem from transcript pruning; in the worst case, character exposure is bounded at $2L$ while token billing may experience higher variance due to tokenizer discrepancies across formats.
2. **Budget-metric circularity [Inference]:** The Gate strictly tracks character budgets ($E \le L$), yet the core value proposition is reported in model tokens. For dense code, tables, and structured JSON, character-to-token ratios vary widely. The character-gate ablation is also relatively thin, evaluated on only 5 tasks $\times$ 3 repeats with a single model (DeepSeek-V4-Flash).
3. **Baseline steering disparity [Inference]:** The Naive baseline operated without system prompt steering, whereas SparseRead benefited from an explicit `SKILL.md` guiding the model to formulate structured read intents. Additionally, the RAG Static baseline was a rigid one-shot retriever, and web search was evaluated against a pre-indexed static corpus rather than a live, volatile web environment.
4. **Generalization variance [Inference]:** 125 total tasks across 5 scenarios on a single primary harness (NanoBot). OpenClaw experienced noticeably lower token savings (30.6% median vs. 65.0% for NanoBot and 65.2% for OpenCode), a discrepancy left largely unanalyzed. Predicting whether a novel agent task will benefit or trigger pathological over-reading remains an open problem.

### Key findings (fact, code-read)
- **Fingerprint [Fact]:** Path+size (`sha1` of `key:size`), not content; content `sha256` only as staleness check around collect reads (`orchestrator.py`).
- **Access-vs-session intent precedence mixed [Fact]:** Gate-level session episode decision OVERRIDES fresh per-access decision (`active_decision = self._active_episode_decision(info) or self.benefit_gate.decide(info)`); changed goal/coverage does reopen path (`bridge/server.py`).
- **Episode [Fact]:** One per conversation with sequence-counter id, reused/updated on semantic change — NOT keyed on `(artifact version, objective)` as paper states.
- **Budget in characters [Fact]:** Budget IS in characters (`SRO_*_BUDGET_CHARS` env-configurable; scout 1800/focus 3500/refine 3500/verify 1200/collect 2800; collection higher), enforced during block selection — but FIRST block always admitted even if it alone exceeds budget, and `slot_digest`/`next_action`/skeleton/serialization overhead not counted. No post-serialization clamp.
- **No 2L worst-case invariant [Fact]:** NO $2L$ worst-case invariant anywhere in code; native fallback explicitly permits full native reads outside any SRO budget; `raw()` window cap 50,000 chars unrelated to $L$.
- **Fallback "retirement" absent [Fact]:** Fallback "retirement" of earlier sparse observations ABSENT — instead readiness gates suppress repeat reads and `policy.py` blocks native re-reads of covered sources.
- **Reader selection [Fact]:** `benefit_gate.py` is a deterministic size/type/goal veto table with hardcoded confidence constants; NO Wilson interval, NO $\hat{p}_{\text{valid}} \ge \tau$ threshold, NO cost estimator $\hat{C}$, NO request groups, NO calibration counter. Size floors (`_DOCUMENT_FORCE_BYTES=4096` etc.) with code comment "These floors sit below the positive QwenClawBench examples" — floors tuned to benchmark.
- **Read Intent Protocol matches (mostly) [Fact]:** Five actions {scout, focus, refine, verify, collect} (`models.py`); `sro_preview`/`sro_read`/`sro_raw` + legacy `sro_card` tools; `EvidencePack` with anchored `EvidenceBlocks` and per-slot `slot_digest` {id, status resolved|partial|missing, candidate, anchor, confidence, verify_ref}; coverage-not-sufficiency semantics present. Gaps: no explicit payload-size or scope-examined fields on `EvidencePack`.
- **Core-side enforcement confirmed [Fact]:** Intent validation + budgets + gates + guards in core `bridge/server.py`; OpenCode adapter is a ~79-line thin subclass (policy mapping only).
- **Reader backends real [Fact]:** Text/PDF (`pdftotext -layout`, `pymupdf` fallback, page anchors `pN:Lx-Ly`); tables/JSON (exact TSV subsets to `.sparseread/sro-calc/` with `row_count`/provenance, "do not reread the source object"); multi-file collections (indexing/ranking/excerpts). No dedicated script-library reader (scripts ingested as collection items).
- **Tests [Fact]:** No test asserts any budget/$2L$ bound; fallback tests cover readiness-suppression reuse only, not prompt-level retirement; no calibration tests. Several tests assert exact QwenClawBench task answers (e.g. "Queen Sibylla", "15 August 1286", "3").

### Critical discrepancy (fact + inference)
- **Benchmark-task literals baked into general core reader [Fact]:** `text.py` candidate-bonus special-cases ("registry", "community-built", "before filtering", "public registry"), scoring boosts ("in return", "spare", "bounty"), penalties ("renew"+"truce"), list-extraction regex (`fortifications|castles|towns|cities|sites`), "typed WebSocket API" API extractor; `collection.py` injects "project alpha" joined term, boosts "underprediction/recalibrat/precipitation/weather". These are QwenClawBench-task literals inside `sparseread-core`.
- **Assessment [Inference]:** Reported benchmark gains may partially reflect task-fitted extraction heuristics, not the general protocol alone.
