## 1. Paper summary (NOOA)

**Frame:** NOOA is a model-agnostic Python framework where an agent *is* a Python object. The paper's central move (Sec 1) collapses prompt templates, tool schemas, callback code, and workflow graphs into one surface: a class. Methods with real bodies = deterministic Python; methods whose body is `...` = an LLM-driven loop filled at runtime (Sec 1, Fig 1).

**The six model-facing ideas** (as NOOA defines them in Sec 2 + Sec 5 rubric + Sec 6 Related Work):

1. **Typed input/output** — Agentic methods carry typed args and a typed return annotation; the runtime validates inputs on every call and validates the return before handing control back (Sec 3.1, 3.6). Validated by the runtime, not the prompt.
2. **Pass-by-reference over live objects** — A CodeAct method receives live Python objects, not serialized text. The model sees only a bounded preview (concrete type, true length, head/tail sample) but operates on the full object in generated code (Sec 3.2). Data size is bounded by the execution environment, not the prompt.
3. **Code as action** — The model acts by writing Python (control flow, loops, inline calls, `asyncio.gather` fan-out) inside a restricted Jupyter-like REPL cell, not by emitting JSON tool calls. `eval`/`exec`/`compile`/`input`/blocking-loop calls are rejected by a safety validator before execution (Sec 3.4).
4. **Programmable loop engineering** — Control flow for single- and multi-agent orchestration is ordinary Python, available to both developer and model with the same primitives. No separate workflow DSL/graph. The model authors `@strategy`-decorated functions and fans them out with `asyncio.gather` (Sec 3.1, 3.4; A.15).
5. **Explicit object state** — Durable state lives as typed fields on the agent instance (`self`), rendered into a bounded per-turn state block that is re-evaluated every LLM turn and held out of history eviction — so the agent stores/inspects/reuses state without reconstructing it from a transcript. Data fields only: attaching method-like callables to `self` is blocked by design (Sec 3.5, A.15).
6. **Model-callable harness APIs for context and events** — `self.context` (static + dynamic blocks) and `self.events` (queryable typed event history) are first-class runtime APIs the model can read and manipulate: `self.events.query(type="PythonOutput", limit=3)`, `self.events.collapse(start, end, summary=...)`, `self.context.set_dynamic("todo", "self.todo.status()")` (Sec 3.2, Fig 4). By default omitted from self-doc until the developer opts them in, then fully model-callable.

**Validated LLM loop (Sec 3.6 + A.15):** When the model calls `return_result(...)`, the harness validates the value against the return annotation; on failure it sends a descriptive error and the loop continues, on success it returns control to the caller. The CodeAct contract is: `execute_python(...)` to continue or `return_result(...)` to terminate — **termination itself is a type-validated action**, not an informal "model stopped calling tools" convention. The paper (Sec 4.2 "Validated termination") credits this as a key differentiator: **OpenCode stops whenever the model responds without a tool call, and 77% of its failed GPT-5.5 Terminal-Bench trials terminated within 10 steps under that rule**; NOOA forces a validated return.

## 3. Contradiction audit

### REFUSED — Idea #6 "model-callable harness APIs" vs the authority invariant

NOOA's sixth idea exposes `self.context` / `self.events` as **model-callable and model-editable** machinery: the model queries event history, collapses event ranges with summaries, and sets dynamic-context blocks that re-render each turn. This **directly conflicts** with this repo's load-bearing safety invariant:

> Model and subagent output may *inform* a later decision, but an executor, policy, or gate applies every transition and side effect … Treat any model-produced artifact as a proposal to be checked and applied, not as an authority that acts on its own.

**Reasoning the repo keeps the divergence (do NOT adopt):** Allowing the model to edit its own context/events would make model output *transition authority* over the very surface that shapes its next turn — a closed loop the repo's entire coordination/safety architecture (read-only coordinator, ownership classification, commit-gate, shell-guard) exists to break. NOOA validates *within* the agent process (Sec 7 concedes its validator "protects the agent loop, not the host"); this repo validates at the *host boundary*. The two philosophies are incompatible at the value-system level, and the repo's choice is load-bearing and correct. Flagged so a future reader does not "adopt idea #6 for parity."

### Other divergences (layer differences, not value conflicts)

1. **Python object model vs rules+Go-renderer** — different abstraction level. NOOA is a Python app framework; this repo is a static Go binary rendering Markdown/JSONC onto OpenCode. They cannot share code.
2. **"Code as action" vs "model output is a candidate"** — complementary layers, not contradictory. Both run safety validators at different boundaries (in-process vs host).
3. **"Explicit object state held out of eviction" vs text-substrate state** — real gap in expressive power, but a durable consequence of the rules+renderer choice, not a fixable defect.
4. **NOOA's introspectable capability surface vs `CapabilityMatrix`** — convergent (see §4 L3 corroboration), not contradictory.

**Net:** One genuine value-system contradiction (idea #6, refused above); the rest are layer differences or convergent designs.

## 4. Actionable learnings

Only items that could actually influence THIS repo. All four are **disciplinary, not architectural** — none require code change.

### L1 — Reframe `behavioral-closure` as a "termination contract" (deferred)

- **Learning:** NOOA Sec 4.2 shows that forcing a *validated, evidence-bearing return* (vs "model stopped calling tools") prevents premature termination — **77% of OpenCode's failed GPT-5.5 Terminal-Bench trials terminated within 10 steps under the stop-on-no-tool-call rule.** This repo already has the analog (`behavioral-closure` token: `verdict:proven` requires `result:proven`, doctor FAILs inconsistency), but frames it as closeout hygiene rather than as a *termination contract* where evidence + verifying command ARE the gate that earns the right to stop.
- **Layer:** Safety (5) + Cognitive (2).
- **Mechanism:** `behavioral-closure` token (internal/cli/doctor_behavioral_closure.go enforces; AGENTS.md "Behavioral closure" section describes).
- **Confidence:** medium. **Effort:** trivial (reframe of existing guidance, no code change).
- **Disposition:** **filed as a defer card** (trigger: next natural edit to behavioral-closure docs/templates) so the one-line reframe rides that edit instead of paying its own ceremony. See related `researches/decisions/2026-07-24-behavioral-closure-pilot.md`.

### L2 — NOOA's memory system is a benchmarked instance of the Cognitive layer (corroboration citation)

- **Learning:** NOOA Sec 3.7 (+11.8 RHAE points on ARC-AGI-3 vs file-based notes) shows deliberate-write + spontaneous-injection + ACT-R activation + decay-based forgetting + typed live references (`kind:key`) resolved at recall time materially beats "MEMORY.md re-injected at session start." **This repo's workstream/claims layer + premise-recheck 4-tuple is the text-protocol precursor of exactly this idea** — so NOOA's result is independent corroboration that the discipline this repo already encodes (deliberate writes, re-derivation, decay) is on the correct side of the tradeoff.
- **Layer:** Cognitive (2).
- **Disposition:** **cite, do not port.** SQLite + vector indexes don't fit a static Go binary's scope. Most of NOOA's memory machinery is out of scope; only the *discipline* is portable, and it is already encoded as the premise-recheck protocol. Filed here as a corroboration citation for the existing memory/claims design.

### L3 — NOOA "tool-as-CLI over tool-as-MCP" validates the exec-family + shell-guard (corroboration citation)

- **Learning:** NOOA Sec 6 argues a CLI is called from code so the model can filter/transform/compose outputs programmatically, while an MCP tool dumps its full JSON result into the context window. **This independently validates this repo's exec-family (exec/exec-ro/exec-sandbox/shell) + shell-guard design** as the correct side of the tradeoff.
- **Layer:** Environment (6) + Safety (5).
- **Confidence:** high.
- **Disposition:** **validation of an existing choice**, not a change. Filed here as a corroboration citation supporting AGENTS.md "Shell, container, and workspace hygiene" and docs/ai/shell-execution.md.

### L4 — "State held out of eviction, rendered fresh each turn" sharpens workstream-eligibility (cross-ref note)

- **Learning:** NOOA's principle ("held out of eviction rather than reconstructed from a transcript") names precisely what `.opencode/state/workstreams/<slug>/brief.md` + `next-slice.md` eligibility-for-compaction is reaching for. The text substrate can't render "live fields," but the *discipline* (keep the operative slice out of compaction, re-derive rather than trust a stale summary) is directly aligned.
- **Layer:** Cognitive (2) + Coordination (3).
- **Confidence:** low–medium.
- **Disposition:** **folded here as a cross-ref note** — the repo already does this under different vocabulary (workstream rules + premise-recheck protocol); no separate defer card warranted.

### Non-learnings (explicitly rejected)
- **Do not** port NOOA's object model, strategies, REPL, or memory subsystem — wrong substrate (Python runtime vs static Go binary + rules), out of scope.
- **Do not** make context/event machinery model-callable (idea #6) — contradicts the load-bearing authority invariant (see §3 REFUSED).
- **Do not** adopt typed model-facing I/O contracts — that is OpenCode's surface (the repo's Environment layer), not the harness's.

## 5. One-paragraph verdict

**Close-and-forget at the level of *adopting* NOOA's design; worth a single reference citation, not a deeper second read or design memo.** NOOA is a model-facing Python agent runtime — a competitor/alternative to OpenCode itself — whereas vh-agent-harness is a rules+renderer harness that installs onto OpenCode and deliberately keeps the model-facing surface at arm's length. The paper's own Appendix A.13 scores OpenCode (this repo's Environment layer), confirming that 5 of NOOA's 6 ideas live at a layer this repo configures but does not own; the 6th (model-callable harness APIs) is a genuine value-system divergence this repo should keep refusing. The only portable substance is disciplinary: NOOA's "validated termination" sharpens the existing `behavioral-closure` framing (L1, deferred), its memory system is a concrete benchmarked instance of what the Cognitive layer's workstream/claims + premise-recheck already gesture at (L2, citation), and its "tool-as-CLI over tool-as-MCP" argument independently validates the exec-family + shell-guard design (L3, citation). None require code change. NOOA and this repo solve different problems at different layers, and the overlap is small, real, and mostly already implemented here under different vocabulary.
