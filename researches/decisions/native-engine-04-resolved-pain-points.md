# 04 — Resolved Pain Points: vh's Documented Structural Limits vs the Native-Engine Program
**Date**: 2026-08-19
**Claim under verification** (operator): "the native-engine program will also help resolve many problems that our harness cannot resolve today."
**Verdict up front**: TRUE for 11 of 16 inventoried pains — the ones whose root cause is "OpenCode owns the LLM/session/tool plane, so the harness can only prescribe discipline." HONESTLY PARTIAL for 3, and UNCHANGED for 5 classes (see §3). Every pain below is cited to its actual doc location; no pain is invented.

## 3. NOT resolved — honest list

1. **The author+reviewer honesty ceiling in its full generality.** A native log proves the *engine* executed something; it cannot prove the human reviewer actually looked, nor that the model's interpretation of a result is correct. The ceiling moves (presence → derivable engine truth) but does not vanish — AGENTS.md's own words survive: the gate verifies structure, humans verify meaning.
2. **Human gates as policy.** Skill-proposal accept/reject, task promotion, protected decisions, the S2 hold — all remain human actions by deliberate design (AGENTS.md skill-authoring intake; formal-verification design condition 1). No engine resolves these; it can only make the evidence better.
3. **Operator attention.** Settlement events notify; they do not decide. The WAITING_ON/blocker-queue bottleneck is human bandwidth, not architecture.
4. **Cross-machine / multi-operator coordination.** Personal-use, single-binary scope (operator decision 1); the file-based coordination model is an explicit carry-over (E11). P9/P15 are therefore only partially addressed.
5. **Model quality itself.** Durable retries make transport reliable; they do not make answers right. dsh's own honesty applies: "cache-damage renders no verdict" (session-cognition headline).
6. **External-world signals.** GPU/thermal/compositor/real-browser interaction inside a *target app* remain outside any engine's observation plane — debugging-loop downgrades and P2's `not-demonstrable` honesty rule survive intact for that class.
7. **Formal verification stays INFORMS-only.** Deliberate authority containment; unchanged (P13).
8. **An operator escape path must survive.** Removing the hatch from agent scopes (P14) is a win; the operator's own bypass channel remains by necessity — containment, not elimination.
9. **New cost inherited: unbounded log growth.** dsh accepts it by design ("log retention absent by design" — session-cognition gap-fill OQ 5 resolution; README known-gaps). The native program trades context-window pain for storage/retention pain; a trim story is an open design question, not a solved one.
10. **Backlog eventual-consistency as filed.** The brief keeps `docs/planning/backlog.md` as canonical ledger with split-commit discipline; the bus makes real-time events *possible* but no committed design adopts them (flagged as follow-up, not resolution).

## 4. Slice prioritization input

(Task numbering: 1 event-log/replay, 2 session/compaction, 3 tool waterfall, 4 async, 5 host protocol, 6 subagents/bus.)

- **Slice 1 — event-log/replay**: kills the *root* of P1/P5/P11 — a ground-truth log exists and replay is deterministic (S1 spike IS this pain's kill criterion); P4 becomes seq-addressable.
- **Slice 2 — session/compaction**: kills P3 (surface-replace with citations), completes P4 (staleness derivable from fold), kills P7 (durable turns, fail-closed flush, interrupted-turn closure, retry-as-numbered-turns).
- **Slice 3 — tool waterfall**: completes P1 (receipts = logged tool events), kills P14 (deny-only lattice makes escape-hatch-class verbs unregisterable), most of P8 (gated catalog + tripwire).
- **Slice 4 — async**: kills P6 outright (async possible at all); hardens P9 (durable job ids + first-wins settlement).
- **Slice 5 — host protocol**: partially resolves P2 (engine-plane user actions observable), kills P16 (typed user-role ingress), enables P12's mock-server/model-request-plane testing to be wired as doctor/runtime observability.
- **Slice 6 — subagents/bus**: kills P10 (provenance-clean reporting), P16 reinforcement (typed sources), partial P9/P15 (durable inboxes; real-time coordination events become possible).

**Reordering arguments (honest):**
- *No reorder needed on pain-kill grounds*: the biggest documented-pain cluster (P1/P3/P4/P5/P11 — the honesty-ceiling admissions that carry the most AGENTS.md ink) is killed by slices 1–3, which is exactly the current order.
- *One pull-forward flag*: the mock-server + model-request-plane + typed-ingress *patterns* (P2/P12/P16 relief) are design specs, not code — they can be harvested into the R0 protocol spec cheaply, matching the brief's existing "optional parallel: land D18/D19/D20 into current doctor" move.
- *One de-prioritization flag (informational, not a recommendation)*: slice 4 (async) kills the fewest *documented* pains; its priority rests on operator demand (decision 5), which is legitimate but should be stated as such.
